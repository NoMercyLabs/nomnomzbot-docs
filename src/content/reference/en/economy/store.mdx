The store connects [channel currency](/reference/economy/currency-and-balances) to things a viewer can trigger, such as a command or pipeline.
An item sets the price, who can buy it, and limits such as stock or a cooldown.
You configure items on the **Store** tab of **Economy**.

The dashboard currently provides item management, but the viewer store still shows **Coming soon** and there is no built-in purchase command.
A working purchase flow therefore needs an integration that submits purchases for signed-in viewers.
If you are setting up everyday viewer rewards entirely through the dashboard, start with [channel-point rewards](/reference/automation/rewards) while that store interface is incomplete.

## Who can use this tab

Anyone who may open the **Economy** page sees the **Store** tab.
A **Moderator**, **Lead moderator**, **Editor** or **Broadcaster** may add, edit, switch and delete items.
The **New item** button, the edit button and the delete button show only to them.
Everyone else sees each item's on or off state in place of the switch, but cannot change it.

## Add a store item

1. Open **Economy** in the sidebar and choose the **Store** tab.
   The **Store items** list shows "Things viewers buy with the currency."
2. Choose **New item**.
   The **New store item** dialog opens.
3. Type a name in **Item name**.
4. Type any short label in **Effect kind**, for example `sound`.
5. Set **Cost** and the other fields (see the table below).
6. Choose **Save item**.
   The dialog closes and the item shows in the list, switched on, with its cost under the name, such as "50 to buy".

**Effect kind** must hold a word before the item saves.
No part of the bot acts on this word.

The bot refuses a second item with the same name in the channel.
It compares names without case and without spaces at the start or end.
A negative cost is refused.
For a first test, save an item with **Cost** 0 and **Who can buy** set to **Moderator**, so only moderators can buy it and nobody pays.

| Label | What it sets | Default |
| --- | --- | --- |
| **Item name** | The name in the list. Required: "Give the item a name." | Empty |
| **About this item** | A short description. | Empty |
| **Effect kind** | A word saved with the item. Required on a new item: "Enter the effect kind." It cannot change later. | Empty |
| **Cost** | How much currency one purchase takes. | 0 |
| **Who can buy** | The lowest role that may buy the item. | **Everyone** |
| **Command or pipeline to run** | A command, pipeline or bot action to run for the buyer after a successful purchase. | None |
| **Cooldown (seconds)** | The time after a purchase before the item can be bought again. 0 is no cooldown. | 0 |
| **Stock** | How many can be bought in total. Empty is no limit. | Empty |
| **Per viewer per stream** | How many one viewer can buy since the channel's latest stream started. Empty is no limit. | Empty |
| **Sort order** | A number saved with the item for its place in the list. | 0 |
| **Item icon URL** | A link to an image for the item. | Empty |
| **Cooldown per viewer** | On: each viewer has their own cooldown. Off: one cooldown covers everyone. | Off |

**Who can buy** lists the roles lowest first, written as the list shows them:

- **Everyone**
- **Subscriber**
- **Vip** (a VIP)
- **Artist**
- **Moderator**
- **LeadModerator** (a lead moderator)
- **Editor**
- **Broadcaster**

There is a current mismatch between this list and the store's purchase check.
The check recognizes **Everyone**, **Subscriber**, **Vip**, **Artist** and **Moderator**.
Choosing **LeadModerator**, **Editor** or **Broadcaster** currently falls back to **Everyone** for the item's role requirement; do not use those three choices to restrict purchases.
The integration still has to pass the bot's separate `economy:catalog:purchase` permission, which every signed-in viewer has by default.

The **Command or pipeline to run** list holds commands, bot actions and [pipelines](/reference/commands/pipelines).
For example, an item can run a pipeline that plays a sound after the purchase succeeds.
The binding is what makes that happen; the required **Effect kind** text does not choose the action.
The linked action gets the purchase details as variables a pipeline can use: `{catalog.item.name}`, `{catalog.item.cost}`, `{catalog.item.id}` and `{catalog.purchase.id}`.

## Connect purchases to an integration

An integration submits each purchase for the viewer who is signed in.
It does this by sending `POST /api/v1/channels/{channelId}/economy/catalog/{itemId}/purchase`, where `{itemId}` is the store item's ID.
The bot resolves that viewer's permissions itself, then applies the item's price and purchase limits.
Configuring an item in **Store** prepares those rules; your integration still needs to give viewers a way to submit the purchase.

## What a purchase does

When a purchase comes in, these checks run in order.
The first check that fails stops the purchase, and the viewer pays nothing.
The channel currency must also be switched on with **Currency on** in [Currency and balances](/reference/economy/currency-and-balances); while it is off, every purchase and refund is refused.

1. The item exists and is switched on.
2. The buyer's role is at least **Who can buy**.
3. The cooldown has run out.
4. Stock is left, when **Stock** is set.
5. The buyer is under **Per viewer per stream**, when it is set.
   The bot counts purchases since the channel's latest stream started.
   It keeps counting after that stream ends, until the next stream starts.
   A channel with no stream record has no per-stream limit.
6. The buyer's wallet is not frozen and holds the cost.
   A frozen wallet cannot spend.
   See [Currency and balances](/reference/economy/currency-and-balances).

When every check passes, the bot takes the cost from the buyer's balance.
It takes one from the stock, when **Stock** is set.
It saves the purchase with the item's name at that moment.
The purchase sends no chat line of its own.

When the item links a command, pipeline or bot action, the bot runs it with the buyer as the person who used it.
Any chat output uses the channel's bot account.
If the linked action fails, the purchase still stands and the cost is not automatically refunded, so test the linked behavior before offering the item to viewers.

The dashboard has no button to refund a purchase.
An authorized integration can submit a refund through the API, which credits the paid amount and restores one unit of limited stock.
A refund does not undo a sound, command or other linked action that already ran.

The current refund path leaves the original purchase marked completed and adds a separate refund record.
The original purchase still counts toward its cooldown and per-stream limit.

The endpoint does not prevent another refund of that original purchase: a repeat call can credit the amount and restore stock again.
If a response is lost, check the balance and purchase history before retrying through an integration.

## Edit a store item

1. Choose the edit button on the item's row.
   The **Edit store item** dialog opens with the item's values.
2. Change the fields.
   **Effect kind** is grayed out and cannot change.
3. Choose **Save item**.
   The dialog closes and the list shows the change.

Emptying **Stock**, **Per viewer per stream**, **About this item** or **Item icon URL** keeps the old value.
Changing **Stock** changes the limit, but does not refill what is left.
Do not add **Stock** to an item that had none, because every later purchase then fails as out of stock.
Make a new item instead.

## Switch an item off or on

Use the switch at the end of the item's row.
A switched-off item stays in the list, and no viewer can buy it.

## Delete a store item

1. Choose the delete button on the item's row.
   A dialog asks "Delete" with the item's name, and says "Viewers can no longer buy it. Past purchases stay."
2. Choose **Delete item**.
   The item leaves the list.

Past purchases keep the name the item had when they were bought.
