Helpers on this page: `{followed_at}`, `{tier}`, `{months}`, `{streak}`, `{message}`, `{also_said}`, `{count}`, `{anonymous}`, `{bits}`, `{gifter*}`, `{viewers}`, `{reward*}`, `{redemption*}`, `{moderator}`, `{duration}`, `{broadcaster}`, `{title}`, `{game}`, `{supporter.*}`, `{provider}`, `{cost}`, `{input}`, `{reason}`, `{obs.event.*}`, `{vts.event.*}`.

Event helpers carry the values of one event, such as the tier of a sub, the bits of a cheer or the viewers of a raid.
You use them in the line of an event response, on the **Event responses** page of the dashboard, and in a pipeline that an event starts.
A few of them also work in Discord notifications.

Each event fills only its own helpers.
When you edit a response, the help under **Your line** says "You can use:" and lists the helpers that event fills.
A helper that the event does not fill is not replaced: the bot sends it exactly as you typed it, braces included.

## Helpers in a chat command

A chat command has no event behind it, so it cannot fill an event helper.
If you copy `{tier}` from a sub response into a chat command, the command does not save.
The dashboard names the helper and says where it works instead, such as event responses, pipelines and Discord notifications.
For a value a command can use, see [Variables and templates](/reference/commands/variables-and-templates).

## Subscriptions and gifts

`{tier}` is the tier number of the sub: `1`, `2`, `3` or `Prime`.
Write the word yourself if you want it, for example `Tier {tier}`.
In a Discord notification the same helper already gives the full words, such as `Tier 1`.

**New Twitch subscriber** fills `{tier}` only.
A viewer who got the sub as a gift is not announced here: **Twitch gift sub received** announces them instead.

**Twitch resub message** fills `{tier}`, `{months}`, `{streak}`, `{message}` and `{also_said}`.
`{months}` is the total number of months the viewer has been subscribed.
`{streak}` is the number of months in a row.
`{message}` is what the viewer wrote with the resub, and it is empty when they wrote nothing.

`{also_said}` is a ready-made clause for that message.
It starts with a space, then reads `They also said: "..."`, with the message in quotes.
It is empty when the viewer wrote nothing, so you can put it straight after a sentence:

```
Thanks {user} for {months} months!{also_said}
```

**Gifted Twitch subs** announces the gifter of a batch of subs.
It fills `{tier}`, `{count}` (how many subs were gifted) and `{anonymous}`.
**Twitch gift sub received** announces each viewer who got a gifted sub.
It fills `{gifter}`, `{gifter.id}`, `{tier}` and `{anonymous}`.

When the gifter stays anonymous, the bot uses the separate responses **Anonymous gifted Twitch subs** and **Anonymous Twitch gift sub received**.
In both, `{anonymous}` is `true`.
In **Anonymous gifted Twitch subs**, the gifter's name is `{user}`, and it is `Anonymous`.
In **Anonymous Twitch gift sub received**, `{gifter}` is `Anonymous` and `{gifter.id}` is empty.

## Cheers

**Cheer** fills `{bits}`, `{message}`, `{also_said}` and `{anonymous}`.
`{message}` is the cheer text with the cheer emotes removed, so `Cheer100 great stream` gives `great stream`.
`{also_said}` works the same as for a resub.
For an anonymous cheer, the viewer's name is `Anonymous`.

## Held messages

A viewer's text can be held by moderation.
While the bot's moderation queue still holds the text of that viewer, `{message}` and `{also_said}` are empty in the response.
The same holds for `{input}` on a reward redemption.
The rest of the line is still sent.

## Follows and raids

**New follower** fills `{followed_at}`.
It is the date and time of the follow, written as a full timestamp, such as `2026-10-06T18:30:00.0000000+00:00`.

**Incoming raid**, **Outgoing raid** and **Raid starts** fill `{viewers}`, the number of viewers in the raid.

## Rewards

**Reward redeemed** fills `{reward}`, `{reward.id}`, `{redemption.id}`, `{cost}` and `{input}`.
`{input}` is the text the viewer typed with the redemption, and it is empty when the reward asks for none.
The responses for a reward that is paused, resumed, switched on or switched off fill `{reward}`, `{reward.id}` and `{cost}`.

## Moderation and duration

**Ban** fills `{moderator}`, `{reason}` and `{duration}`.
A timeout uses the same **Ban** response.
`{duration}` depends on the action:

| Event | `{duration}` gives | Example |
| --- | --- | --- |
| A ban | the word `permanent` | `permanent` |
| A timeout | the length in whole minutes, or in seconds when it is not whole minutes | `10 minutes` |
| **Stream ends** | the length of the stream, in hours, minutes and seconds | `02:15:30` |
| A Discord stream-end notification | the length of the stream, in hours and minutes | `2h 15m` |

`{moderator}` is the display name of the moderator who acted.
`{reason}` is empty when the moderator gave no reason.
**Unban** fills `{moderator}` only.

The bot sends a ban, timeout or unban response only for an action the bot itself made.

## Stream start and end

**Stream goes live** fills `{broadcaster}`, `{title}` and `{game}`.
The title and the category are the ones on the stream when it goes live.
**Stream ends** fills `{broadcaster}` and `{duration}`.

## Supporters

Supporter events come from a connected tip, membership, merch or charity service.
Each one starts the response for its own kind and also the response for any supporter event.
They fill the `{supporter.*}` helpers, and `{user}` is the supporter's name.

`{supporter.amount}` is the amount in whole currency units, with no trailing zeros.
So 5 euro gives `5`, and 12.50 euro gives `12.5`.
`{supporter.currency}` is the three-letter code, such as `EUR`.
`{supporter.amount}`, `{supporter.currency}`, `{supporter.tier}` and `{supporter.quantity}` are empty when the service does not send them.

## OBS and VTube Studio fields

An OBS event response fills `{obs.event.type}` and one helper for each field that OBS sends with the event, such as `{obs.event.sceneName}`.
A VTube Studio event works the same way, such as `{vts.event.modelName}`.
The field names come from OBS and VTube Studio, and each event lists its own under **Your line**.
A text field gives its text, an empty field gives nothing, and any other value gives its raw text.

## Reference

`{provider}` names the platform that sent the event, such as `twitch` or `kick`.
It works in event responses only.

The examples show the shape of a value.
Your results depend on the channel and the event.
**Use in** lists the places that accept each helper.
For viewer-written text, the [Viewer Templates setting and permissions](/reference/settings/features) also apply.

| Helper | What it gives | Example | Use in |
| --- | --- | --- | --- |
| `{also_said}` | A space, then `They also said:` and the viewer's message in quotes; empty when there is no message | ` They also said: "Great stream!"` | event responses, pipelines |
| `{anonymous}` | `true` when the gifter or cheerer stayed anonymous, otherwise `false` | `false` | event responses, pipelines |
| `{bits}` | How many bits were cheered | `100` | event responses, pipelines, Discord |
| `{broadcaster}` | The display name of the channel that went live or ended its stream | `Example_Channel` | Discord, event responses, pipelines |
| `{cost}` | The channel-point reward's cost | `500` | event responses, pipelines |
| `{count}` | How many subs were gifted in one batch | `12` | event responses, pipelines, Discord |
| `{duration}` | `permanent` for a ban, a length for a timeout, or the length of the stream that ended | `10 minutes` | event responses, pipelines, Discord |
| `{followed_at}` | The date and time of the follow, as a full timestamp | `2026-10-06T18:30:00.0000000+00:00` | event responses, pipelines |
| `{game}` | The stream category when the stream goes live | `Just Chatting` | Discord, event responses, pipelines |
| `{gifter}` | Who gifted the sub to this viewer; `Anonymous` when the gifter stayed anonymous | `Example_Supporter` | event responses, pipelines |

| `{months}` | The total months the viewer has been subscribed | `12` | event responses, pipelines, Discord |
| `{obs.event.<field>}` | One field that OBS sent with the event, such as `{obs.event.sceneName}` | `{obs.event.sceneName}` gives `Scene 1` | event responses, pipelines |
| `{provider}` | The platform that sent the event | `twitch` | event responses |
| `{reason}` | The reason the moderator gave; empty when there is none | `Spam` | event responses, pipelines |

| `{supporter.kind}` | The kind of supporter event: `tip`, `membership`, `merch` or `charity` | `tip` | event responses, pipelines |

| `{supporter.name}` | The supporter's display name | `Example_Supporter` | event responses, pipelines |

| `{viewers}` | The number of viewers in the raid | `25` | event responses, pipelines, Discord |
