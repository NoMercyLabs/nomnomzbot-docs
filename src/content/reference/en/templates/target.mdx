Helpers on this page: `{target}`, `{target.*}`.

The target is the person a reply is about when that person is not the one who used it. These helpers work in commands, event responses, pipelines and webhooks. A timer has no target, so they are not offered there.

In a command, the target is the first word typed after the command, with any `@` removed. In `!hug @someone`, the target is `someone`. The bot never fills in the caller when no name is given, so `!hug` on its own has no target at all. In an event response, the target is the person the event is about, such as the viewer who followed.

## Write a reply about someone else

For a command used as `!hug @someone`, try this reply:

```
{user} sends a hug to {target.displayname}.
```

The caller's name fills `{user}`, and the named person's display name fills `{target.displayname}`. If the bot has never seen that person, it asks Twitch for the display name. It shows the word as typed only when no Twitch account has that name or the lookup fails.

Now someone types `!hug` with no name. `{target.displayname}` is empty, so the reply reads "ViewerOne sends a hug to ." To cover both cases, check `{target}` first with [the if helper](/reference/templates/if):

```
{if:{target}|{user} sends a hug to {target.displayname}.|{user} sends a hug to the whole chat.}
```

## When nobody is named

Without a target, the helpers give these results:

- `{target}`, `{target.displayname}` and the three message helpers are empty.
- `{target.known}` is `false`.
- The pronoun helpers use the neutral words they, them, their, person and are, and `{target.verb:<sing|plur>}` takes the second form.
- `{target.mention}`, `{target.shoutoutLink}` and `{target.link}` stay in the reply as written, braces and all.
- `{target.data.<key>}` is empty.
- These stats read as nothing recorded: `{target.messages}`, `{target.commands}`, `{target.botpercent}`, `{target.redemptions}`, `{target.songrequests}`, `{target.days}` and `{target.avgperday}` are `0`, `{target.watchtime}` is `0m` and `{target.firstseen}` is `unknown`.
- `{target.stats.bits}`, `{target.stats.streak}`, `{target.stats.lastSeen}` and `{target.activity.level}` stay in the reply as written, with no viewer data read at all.
- `{target.name}`, `{target.id}`, `{target.followAge}` and the helpers that read the person's Twitch account, channel, points or channel record stay in the reply as written.

## Who the bot can read

The account, channel, points and stats helpers read what the bot has stored about the person. They work for someone the bot has a record of, which is when `{target.known}` is `true`. For a Twitch account the bot has not stored yet, `{target.id}`, `{target.name}` and `{target.displayname}` are filled in from Twitch. `{target.mention}`, `{target.link}` and `{target.shoutoutLink}` are built from the name. `{target.known}` is `false`. The Twitch profile and channel helpers read the Twitch ID in the stored record, which this person lacks, so `{target.avatar}`, `{target.bio}`, `{target.color}`, `{target.createdAt}`, `{target.accountAge}`, `{target.game}` and `{target.title}` are empty, `{target.isLive}` and `{target.isFollower}` are `false` and `{target.viewers}` is `0`. The stats that count activity give `0`, `0m` or `unknown`, and `{target.followAge}` stays in the reply as written.

The points helpers read the named person's balance in the bot's [channel currency](/reference/economy/currency-and-balances). That balance is separate from Twitch Channel Points.

The examples show possible values; your results depend on the channel and the person. **Use in** lists the template fields that accept each helper.

## Pronouns and grammar

These read the pronouns saved for the target. When the target has none saved, they use the neutral words. To learn where the bot gets pronouns and how to write a reply that fits he, she and they, read [Pronouns in templates](/reference/templates/pronouns).

| Helper | What it gives | Example | Use in |
| --- | --- | --- | --- |
| `{target.subject}` | The subject pronoun | `they` | Commands, event responses, pipelines, webhooks |
| `{target.object}` | The object pronoun | `them` | Commands, event responses, pipelines, webhooks |
| `{target.possessive}` | The possessive pronoun | `their` | Commands, event responses, pipelines, webhooks |
| `{target.presentTense}` | `is` or `are`, to agree with the pronoun | `are` | Commands, event responses, pipelines, webhooks |
| `{target.tense}` | `is` or `are` while your channel is live, `was` or `were` while it is offline. In a shoutout it follows the live state of the person shouted out | `are` | Commands, event responses, pipelines, webhooks |
| `{target.genderedTerm}` | A gendered word for the person | `person` | Commands, event responses, pipelines, webhooks |
| `{target.verb:<sing\|plur>}` | The first form for a singular pronoun such as he or she, the second for they | `{target.verb:has\|have}` gives `have` | Commands, event responses, pipelines, webhooks |

The three message helpers read the person's chat in your channel and skip commands and deleted messages.

| Helper | What it gives | Example | Use in |
| --- | --- | --- | --- |
| `{target.lastmessage}` | Their most recent message. Over 80 characters, it is cut to 77 and ends in `...` | `see you tomorrow` | Commands, event responses, pipelines, webhooks |
| `{target.lastmessage.full}` | Their most recent message that is not empty and does not start with a link, never cut | `see you tomorrow` | Commands, event responses, pipelines, webhooks |
| `{target.randommessage}` | A random message longer than 5 characters that does not start with a link. Over 200 characters, it is cut to 197 and ends in `...` | `nice play` | Commands, event responses, pipelines, webhooks |
