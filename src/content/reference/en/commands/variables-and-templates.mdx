A reply is a template: plain text with helpers in it (see [Create a command](/reference/commands/create-a-command)).
A helper is a name in braces, such as `{user}`.
The bot puts the real value in its place wherever a viewer sees or hears the text: in chat, on an overlay or read aloud.

```text
Welcome {user}! Today we play {stream.game}.
```

The bot types this as "Welcome Example_Viewer! Today we play Just Chatting."
It types the line in the channel's one bot voice.

## How a template becomes the text a viewer sees or hears

1. The bot reads the template once and finds every helper.
2. It fetches only the values that the template names.
3. It puts each value in the place of its helper.
4. It shows the result where it belongs: in chat, on an overlay or read aloud.

A helper that the bot does not know stays in the line exactly as you wrote it.
So a typo such as `{usr}` shows as `{usr}`.
The **Reply** field warns you about this before you save (see [Create a command](/reference/commands/create-a-command)).

In an [event response](/reference/automation/event-responses), a value that the event carries wins over a value the bot looks up itself.

### Where a reply goes

| **Send the reply to** | What the bot does with the template |
| --- | --- |
| **Twitch chat** | Fills it in once, as plain text, and types it in chat. |
| **Chat overlay** | Fills it in for the overlay only. |
| **Both** | A plain reply: fills it in once and shows the same text in both places. A reply with HTML: fills it in twice, plain text for chat and HTML for the overlay. |
| **Nowhere** | Fills in nothing. |

HTML is markup such as `<b>bold</b>` that styles text on the chat overlay; a plain reply does not need it.
When a reply holds HTML, the values that come with the command (the name and the words after the command) are HTML-encoded.
So a `<` in those values shows as the character `<`, not as the start of a tag.
Values the bot looks up, such as a last chat message, are not encoded; the overlay keeps only its safe tags, such as `<b>`.

### Names in chat and in speech

Twitch pings a person in chat only by their login name.
When a display name differs from the login by more than letter case, the chat line uses the login.

This applies to `{user}`, `{target.name}` and `{target.displayname}` in chat.
When a pipeline reply is read aloud, the speech uses the display name of the person who used the command.
When a shoutout is read aloud, the speech uses the target's display name.

### Special characters

Put a backslash before a character to type it as itself: `\{`, `\}`, `\|`, `\:` and `\\`.
A brace that is never closed, or empty braces, stay in the line as text.
A helper can hold another helper, up to 8 levels deep.

## Type a helper with input

A helper name may hold dots, such as `text.upper`.
A colon ends the name, and the text after it is the input, such as `{text.upper:hello}`, which gives `HELLO`.

| You write | What it does |
| --- | --- |
| `{if:value\|then\|else}` | Shows one text or the other. |
| `{default:value\|fallback}` | Shows the fallback when the value is empty. |
| `{set:name=value}` | Keeps a value for the rest of the reply and prints nothing. |

The **Reply** field lists every helper with an example, for the place you are writing in.

## Where you can use templates

Each place has its own set of helpers.

| Place | What it has |
| --- | --- |
| Command replies | Most helpers on the helper pages, with the words after the command. A few helpers that belong to an event are not available. |
| [Event responses](/reference/automation/event-responses) | The channel and viewer helpers, and the values of the event (a raid, a sub, a cheer). No words after a command. |
| [Timers](/reference/automation/timers-and-chat-triggers) | The channel, time, random, counter and list helpers. No person and no words after a command. |
| [Pipeline steps](/reference/commands/pipelines) | The helpers of the trigger the pipeline is bound to: a command, an event or a timer. |
| Discord notifications | The channel, time, random, counter and list helpers, and Discord-only helpers such as `{channel.url}`. |
| Webhook bodies | The channel, person, time, random, counter and list helpers. No event values and no words after a command. |

## Find a helper

Every helper has its own row on the helper pages, with what it gives and an example.
There is one page for each type of helper, and the type is the first word of the helper name.
Start with the overview.
See [Template helpers](/reference/templates/overview).

| You want | Start here |
| --- | --- |
| The name, pronouns, follow age or stats of the person who used the command | [User helpers](/reference/templates/user) |
| The same for the person a command names | [Target helpers](/reference/templates/target) |
| A line that reads right for he, she and they | [Write correct sentences](/reference/templates/user#write-correct-sentences) |
| The stream title, the game or the uptime | [Stream helpers](/reference/templates/stream) |
| The words typed after the command | [Command word helpers](/reference/templates/args) |
| A value from a follow, sub, cheer or raid | [Event helpers](/reference/templates/event) |
| The time and date | [Date and time helpers](/reference/templates/date) |
| A choice or a fallback | [Condition helpers](/reference/templates/if) |
| A random pick | [Random helpers](/reference/templates/random) |
| Changed text | [Text helpers](/reference/templates/text) |

Scripts and widgets use the same helpers (see [SDK for widgets, actions and templates](/reference/code/sdk-widgets-actions-templates)).

## Troubleshooting

::Troubleshooting

**Chat shows the name in braces, such as `{usr}`.**
The bot does not know that helper, so it typed it as written.
Check the spelling against the [helper pages](/reference/templates/overview).

::
