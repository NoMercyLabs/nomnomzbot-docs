---
title: Create a command
description: Make a chat command, change what triggers it and what the bot answers, and switch it off, copy it or delete it.
---

Commands live on the **Commands** page in the dashboard, under the **Channel commands** tab.
A new command is on the moment you create it.

## Before you start

By default, a **Moderator**, **Lead moderator**, **Editor** or **Broadcaster** can make and change commands.
The broadcaster can change who may do this on the [Permissions](/reference/settings/permissions) page.
A **VIP** can be allowed to see the list, but not to change it.

While you're offline, only the broadcaster, moderators and lead moderators get an answer from a command.
An **Editor** who is not also a moderator gets no answer then, and neither do viewers.
To let everyone use commands while you're offline, turn on **Keep commands and rewards on while offline** in [Bot basics](/reference/settings/bot-basics-and-personality).

## Create a command

Start with a plain reply that holds your stream times.
Leave the other fields of the dialog at their defaults until the bot answers in chat.

The name must have no spaces, be at most 100 characters long, and be different from every other channel command.
You leave out the `!`: with the channel's usual prefix, chat types `!schedule` for the name `schedule`.
The dialog makes the name lowercase and drops a leading `!`, so `!Schedule` is saved as `schedule`.
A channel command can also share its name with one of the bot's system commands.
Which one answers is on [Built-in commands](/reference/commands/built-in-commands).

1. Open **Commands** in the sidebar.
   The page opens on the **Channel commands** tab.
2. Choose **New command** at the top of the page.
3. Type `schedule` in **Name**.
4. Leave **What it does** at **Sends a reply**, and write your times in **Reply**.
   For example: `I stream on Tuesdays and Thursdays at 19:00 Amsterdam time.`
5. Choose **Create command**.
   The new command opens in the editor, already switched on.

Now type `!schedule` in your channel's chat, and the bot answers with your reply.
If you're offline, test as the broadcaster or a moderator: an **Editor** who is not also a moderator gets no answer until you're live.

If the bot refuses the name, the dialog stays open and tells you why.

### Other kinds of reply

The choice you leave at **Sends a reply** in the **New command** dialog is called **Reaction** in the editor, and there its options have shorter names.

| **What it does** (dialog) | **Reaction** (editor) | What you fill in |
| --- | --- | --- |
| **Sends a reply** | **Text** | **Reply**: one reply, up to 500 characters. |
| **Sends a random reply** | **Random reply** | **Reply 1**, **Reply 2** and so on. Choose **Add a reply** for each new one. In the editor, the **Random replies** field counts them, and **Edit replies** opens the list. The bot picks one reply each time. |
| **Runs a pipeline** | **Pipeline** | **Pipeline**: the [pipeline](/reference/commands/pipelines) to run. It sends its own messages. |
| **Runs a code script** | **Code script** | **Script**: a script from the **Scripts** page. |

A reply can also hold helpers.
Put `{stream.game}` in a reply, and the bot swaps in your current category each time the command runs.
Every helper is listed on [Variables and templates](/reference/commands/variables-and-templates).
A list of lines that several commands share is a [pick list](/reference/commands/pick-lists).

## Change a command

1. Choose the command in the list.
   **Search commands** above the list finds it by name.
2. Change the fields you want.
   The footer counts them, for example "2 unsaved changes".
3. Choose **Save changes** at the right of the footer.
   The count leaves the footer.

**Discard**, next to **Save changes**, puts every field back as it was saved.
If the bot refuses a change, the editor shows the reason and keeps your edits in the form.

| Field | What it sets | Default |
| --- | --- | --- |
| **Who can use it** | The lowest role that may run the command. | **Everyone** |
| **Reaction** | How the bot answers, as in the table above. | **Text** |
| **Send the reply to** | **Twitch chat**, **Chat overlay**, **Both** or **Nowhere**. | **Twitch chat** |
| **Read it aloud** | The reply also plays as speech on your stream. | Off |
| **Trigger and cooldowns** | A group you open: **Prefix**, **Match**, **Chat cooldown (seconds)** and **Per-person cooldown (seconds)**. | **Prefix** at **Channel default**, **Match** at **Starts with**, and both cooldowns at 0, shown as "No cooldown" |

**Read it aloud** speaks a reply only after it was sent to Twitch chat.
With **Send the reply to** at **Chat overlay** or **Nowhere**, nothing is spoken.
The two cooldowns are explained on [Cooldowns and permissions](/reference/commands/cooldowns-and-permissions).

A command the bot added from a preset also has **Reset to preset** in the footer.
It lists the settings that go back to the preset before you confirm.

## Choose what triggers it

Open **Trigger and cooldowns** in the editor.
It holds two choices: **Prefix** and **Match**.

With **Prefix** you choose what chat types before the name.

| **Prefix** | Chat types |
| --- | --- |
| **Channel default** | The channel's **Command prefix** from Bot basics, then the name. It is `!` when the channel has set none. |
| **Custom** | Your own **Custom prefix**, up to 8 characters, then the name. |
| **None** | The name alone. |

With **Match** you choose how the message must look, and letter case never matters.

| **Match** | The command runs when the message |
| --- | --- |
| **Starts with** | begins with the prefix and the name, then a space or nothing. Text after the name goes to the command. This is the default. |
| **Exact** | is the prefix and the name, and nothing else. |
| **Contains** | has the prefix and the name as a whole word anywhere. |
| **Regex** | fits the pattern in **Regex pattern**. |

The **New command** dialog has the same **Prefix** and **Match** choices, so you can set them before you create the command.

With **Regex**, the bot ignores the prefix and the name and tests only your pattern against the whole message.
So the pattern has to hold your channel's **Command prefix** itself.

### Answer to two words

This makes one command answer both `!schedule` and `!times`.
The example uses `!` because that is the usual **Command prefix**.
If your channel uses a different one, type your prefix where the pattern has `!`.
A prefix such as `?`, `.` or `$` has its own meaning in a pattern, so put a `\` before it, as in `^\?(schedule|times)$`.

1. Choose the command in the list.
2. Open **Trigger and cooldowns**.
3. Set **Match** to **Regex**.
4. Type this pattern in **Regex pattern**:

   ```text
   ^!(schedule|times)$
   ```

5. Choose **Save changes**.

The `|` separates the two words, and the `^` and `$` tie the pattern to the start and the end of the message.
Without them, the pattern also matches a message that only contains `!times` somewhere in the middle.
Because of the `$`, a message with more text after the word, such as `!schedule please`, does not run the command.

A custom prefix or a regex pattern left empty stops the save.
The dialog shows "Fill in the custom prefix or the regex pattern you picked.", and in the editor you cannot choose **Save changes** until you fill it in.

## Switch a command off

Each row in the list has a switch, and the editor has the same switch, **Enabled**, at the top.
Both save at once, without **Save changes**.
A command that is switched off stays in the list, marked **Off**, and answers nobody.
Switch it on again the same way.

The bot refuses to switch a command off while a reward, a timer or another item still runs it.
The switch flips back, and "A change was not saved" appears.
That message does not say which items run the command, so look for the command on the five pages in this table.
Move or remove each item that runs it, then switch the command off.

| Kind of item | Sidebar page |
| --- | --- |
| rewards | **Channel points** |
| timers and chat triggers | **Triggers and timers** |
| event responses | **Event responses** |
| giveaways | **Giveaways** |
| catalog items | **Economy** |

A run that a pipeline scheduled for later also blocks the switch while it still waits.
No page lists these runs.
Wait until the run has fired, then switch the command off.

## Copy a command

Open the command and choose **Duplicate** in the footer.
A copy named after the command with `-copy` at the end opens in the editor.
For `schedule`, the copy is `schedule-copy`, and chat types `!schedule-copy`.

The copy starts switched off, and its reply goes to **Twitch chat**.
It keeps the other saved settings.
If a command with that name already exists, the bot refuses the copy and the editor shows why.

## Delete a command

1. Open the command and choose **Delete** at the left of the footer.
   The dialog asks "Delete !schedule?" and warns: "The command is removed for good. Chat can no longer use it."
2. Choose **Delete command**.
   The editor closes and the command leaves the list.

While items still run the command, the dialog does not open.
The editor names each kind of item, how many there are and up to five of their names.
Move or remove them on their own page, from the table under [Switch a command off](#switch-a-command-off), then delete again.
For a scheduled run that still waits, wait until it has fired, then delete again.

## Troubleshooting

::Troubleshooting

**The command does nothing in chat.**
Check these, in order:

1. The switch in the list. A command marked **Off** answers nobody.
2. **Who can use it**. The person's role must be at least that role.
3. The prefix and the match. They must fit the message chat typed.
4. **Send the reply to**. **Chat overlay** and **Nowhere** send nothing to Twitch chat.
5. The cooldowns. They hold viewers, not you or your moderators.
6. Whether you are live. While you're offline, only the broadcaster, moderators and lead moderators get an answer, unless **Keep commands and rewards on while offline** is on.

::
