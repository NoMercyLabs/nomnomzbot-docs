You read the history of your channel on the **Event journal** page in the settings sidebar.
It sits in the **Access** group.
The page has two tabs.

| Tab | What it holds |
| --- | --- |
| **What happened** | The list of everything the bot saw in your channel, newest first. |
| **Backup and rebuild** | Save or load the journal, rebuild the pages built from it, and copy history from the old bot. |

## What the event journal is

The event journal is the record of everything that happened in your channel.
Each follow, chat message, raid, ban and settings change is one event in it.
The journal only grows: the tools on this page add events or rebuild other pages from it.

Viewer profiles, analytics and the event log are built from the journal.
When the journal gets new events from a file, those pages show them only after a rebuild.

## Who can use this page

The **Broadcaster** may open the page and use every button on it.
The broadcaster cannot give the save, load and old-history buttons to a lower role.
The roles are explained on [Permissions](/reference/settings/permissions).
The way around the dashboard is on the [Dashboard tour](/reference/getting-started/dashboard-tour).

## Read what happened

1. Open **Settings**, then **Event journal** in the settings sidebar.
   The **What happened** tab opens with the newest events at the top.
2. Read each line.
   It shows who did it, what happened, and when.
3. Use **Previous** and **Next** at the bottom to move between pages.
   The footer shows "Page 1 of" and the number of pages.

The person on a line is the viewer or user the bot saved with the event.
A line with no person shows **Bot** when the bot made the change, or **API key** when a tool with an API key made it.
Older events can have no person and no badge.

The same event from the same place and the same person, several times in a row, shows as one line.
That line ends with the count, such as "10 times".

### Filter the list

| Filter | What it does | Default |
| --- | --- | --- |
| **Event** | Shows one kind of event, such as **New follower** or **Incoming raid**. | **All events** |
| **Source** | Shows events from one place. | **Everywhere** |
| **From date** | Shows events from this day on. | Empty |
| **To date** | Shows events up to this day. | Empty |
| **Show bot activity** | Shows the bot's own upkeep events too. | Off |

**Source** has these choices: **Twitch**, **Twitch chat**, **The bot**, **A webhook**, **A linked bot** and **An import**.

A change to a filter takes you back to page 1.
**Clear filters** shows when **Event**, **Source**, **From date** or **To date** is set.
It resets those four filters.
It does not change **Show bot activity**.
The dashboard remembers your filters on this device.

**Show bot activity** is off by default.
Bot activity is every event that is not on the **Event** list.
While it is hidden, the footer says how many entries it hid on the page.

When nothing matches, the list shows "No events match these filters."

## Save the journal to a file

1. Open the **Backup and rebuild** tab.
2. In the **Journal file** card, choose **Export journal**.
   The card shows a clock while the bot prepares the file.
   A large journal can take a few minutes.
3. The download starts by itself.
   The card shows how many events it saved.

The file holds the whole journal of the channel, one event per line.
Keep it as a backup, or load it into another NomNomzBot.

## Load a saved journal

1. On the **Backup and rebuild** tab, in the **Journal file** card, choose **Import journal**.
2. Pick a journal file you saved before.
   The card shows how many lines it read, how many events were new, how many were already there, and how many it upgraded to the current format.

Loading adds only the events that are missing.
An event that is already in the journal is skipped, so you can load the same file twice.
If one line in the file fails, nothing from the file is added.

After a load, choose **Rebuild pages** (see the next section), so the new events show up.

## Use the pages built from the journal

The **Pages built from the journal** card has two buttons.

| Button | What it does |
| --- | --- |
| **Replay imported events** | Runs the imported events through the bot again, so triggers and replies fire for them. |
| **Rebuild pages** | Clears the pages built from the journal and builds them again from the first event. |

**Replay imported events** handles only the imported events that were not replayed before.
Choosing it again with nothing new imported does nothing.
When it ends, the card shows how many events it applied.

Replies that fire during a replay are lines the bot types in chat, in the channel's one bot voice.

### Rebuild the pages

1. Choose **Rebuild pages**.
   A dialog asks "Rebuild the pages built from the journal?"
2. Choose **Rebuild pages** in the dialog.
   The card lists each rebuilt page with the number of events applied to it.

The journal itself stays as it is.
Only the pages built from it are cleared and filled again.
Viewer profiles and analytics show partial numbers until the rebuild ends.

## Copy history from the old bot

The **History from the old bot** card copies the channel history of the old bot into the journal.
Choose **Import old history** to run it.

The card then shows how many rows it read, how many it imported, how many were already there, and how many it did not recognize.
It also shows how big the journal was before and after.
Each kind of row it did not recognize gets its own line with a count.

Running it again adds nothing twice.
The bot only reads the old bot's history file.
It never changes that file.
Run **Rebuild pages** afterward, so the old history shows up on the other pages.

::Troubleshooting

**Import old history shows an error in red.**
The bot could not find the old bot's history file.
Copy the error text and send it to the person who runs the bot for you.
They can put the file where the bot looks for it, then you choose **Import old history** again.

::
