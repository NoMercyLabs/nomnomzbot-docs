---
title: Widgets and alerts
description: What a widget and an alert are, how to add and test them, how to preview a change, and how to replay an alert.
---

A widget is a small part of your stream that the bot updates, such as an alert card, a chat box or a now-playing display.
It runs on an [overlay page](/reference/overlays/set-up-overlays) loaded in OBS.
An alert is the notification a widget shows when an event happens, such as a follow or a cheer.

For a working alert you need both the event and somewhere to display it.
The bot receives the follow or other event, and the alert source draws the notification on your stream.
An [event response](/reference/automation/event-responses) can add a chat reply, speech or other actions alongside that visual notification.

## Set up the supplied alerts

Open **OBS**, choose **Overlays in OBS**, and find **Alerts** under **Required overlays**.
Choose **Connect**, copy the address, and add it as an OBS **Browser** source using the dimensions and settings in the dialog.
[OBS browser source](/reference/overlays/obs-browser-source) gives the full walkthrough.

The supplied alert source handles follows, subscriptions, gifts, cheers, raids and supporter events.
It queues its cards so they appear one at a time.
Keep the browser source loaded while you stream so it can receive those events.

The required alert source has a connection dialog on the **OBS** page, but the current dashboard does not expose its settings in the custom **Overlays** editor.
The **Configure** button on its row opens the same **Set up Alerts in OBS** dialog as **Connect**: the address, the size and the OBS boxes.
It does not change the colors, the events or the alert text.

## Pick a theme

Every supplied widget that draws something has a **Theme** setting.
Find it under **Settings** of an overlay you open on **Overlays**.
The required overlays on the **OBS** page are not listed on **Overlays**.
They are Alerts, TTS caption, Media share, Stage, Bot Audio and Music Player.
For now you cannot change their theme in the dashboard.
The four that draw (Alerts, TTS caption, Media share and Stage) keep the default, **Sticker**.
Bot Audio and Music Player play sound only, so they have no theme.

The help text says: "The look of this widget. Pick the same theme on every widget for one matching set."
The **Chat box** has a second **Theme** setting with **Dark**, **Light** and **Transparent**.
That one sets the chat colors.
The overlay theme is the one with **Sticker**, **Ink**, **Print** and **Classic**.

| Theme | Look |
| --- | --- |
| **Sticker** | White card, bold outline. This is the default. |
| **Ink** | Black pills, quiet. |
| **Print** | Lime poster, halftone dots. |
| **Classic** | Dark see-through panel. |

A widget whose code you changed keeps its own look, because it keeps its own source.

## Customize an overlay you already have

For an overlay listed on **Overlays**, start with **Settings** to change the options it exposes.
You can change those options without writing code.
When the available options are not enough, duplicating it gives you a copy whose code you can edit:

1. Open that overlay and choose **Duplicate**, as [Copy an overlay](/reference/overlays/set-up-overlays#copy-an-overlay) explains.
   The copy opens with the same code.
2. Choose **Edit code** on the copy and change its code, as [Change the code](/reference/overlays/set-up-overlays#change-the-code) explains.
   After you save, the editor shows "Saved and compiled. The overlay now runs this version."
   What the code can use is on [Widgets, actions and templates](/reference/code/sdk-widgets-actions-templates).
3. Add the overlay's address in OBS, as [OBS browser source](/reference/overlays/obs-browser-source) explains.

The **Gallery** entry in the sidebar shows a **Coming soon** page.

## What a widget reacts to

A widget lists the events it listens to under **Reacts to** of an open overlay.
The bot gives the widget a kind from those events.
An open overlay shows the kind as a badge on the row under its name.

The first kind in this table with an event the widget listens to wins.

| Kind | The widget listens to |
| --- | --- |
| **TTS speaker** | Text-to-speech lines. |
| **Chat box** | Chat messages. |
| **Now playing** | The song that plays now. |
| **Alerts** | Follows, subs, resubs, gifts and cheers. |
| **Reward** | Channel point redemptions. |
| **Game** | Chat games. |
| **Feather** | Events listed under **Reacts to** as `feather show`, `feather steal` or `feather event`. |
| **Hype train** | Hype trains. |
| **Leaderboard** | A leaderboard that is shown. |
| **Poll** | Polls and predictions. |
| **Raid** | A raid recap that is shown. |
| **Song queue** | The song request queue. |

These are all 12 kinds.
A widget that matches none of them shows no badge.

## Where an alert comes from

An event response chooses the bot's response to a channel event.
An alert widget listens for the events it supports and presents them on the stream.
Changing a chat response does not connect an OBS source; changing a browser source does not write a chat reply.
Set up both parts when you want both, using [Event responses](/reference/automation/event-responses) for the reply or automation.

## Test an alert

Use **Test** beside an event under **Reacts to**, as [Test an event](/reference/overlays/set-up-overlays#test-an-event) explains.
A **Moderator** or higher may send a test.
On the event ticker and the sub train, a test shows for 10 seconds and never joins the real ticker or train.
A test never adds to a goal bar total or a label count.
A label shows the test name only for a short time.

## Preview a change

The code editor that **Edit code** opens has a fire bar.
The fire bar sends the same sample events as **Test**, but only to the preview in the editor.
When the samples do not load, the editor shows "The sample events could not be loaded, so the fire bar sends nothing."

What a widget's code can use is listed on [Widgets, actions and templates](/reference/code/sdk-widgets-actions-templates).

## Replay an alert

You replay a past event from the **Home** page.
The **Events** page has the same **Replay** button on each row.
Choose **All events** on **Home** to open it.
It lists every event of this stream and of the stream before it.

1. Open **Home** and find the event in the **Happening now** panel.
   When you are offline, the panel is called **Last stream**.
2. Choose the **Replay** button at the end of the event's row.
   A message counts what was sent again.

| Count in the message | What it counts |
| --- | --- |
| chat messages | Chat lines of the event response. |
| voice | Text-to-speech lines of the event response. |
| overlays | Alerts the event response showed on your overlays. |
| widgets | Saved alerts sent again to your widgets. |

A replay does not create a second real follow, subscription or redemption.
It can run the response again, including a command, action or pipeline attached to that response.
Those actions can have real effects, so check a response that changes balances or other channel state before replaying it.
A gift bomb is one viewer gifting several subs at once.
Its replay shows the gifter first, then each recipient, in the original order.

| Message | Meaning |
| --- | --- |
| "Nothing to replay for this event." | The bot has no saved copy of this event and no saved alert for it. |
| "Found the event, but there was nothing to show again: no response is set up for it and no alert was saved." | The event has no response and no saved alert. |
| "Could not replay this event." | The replay failed. |

A **Moderator** or higher sees the **Replay** button.
