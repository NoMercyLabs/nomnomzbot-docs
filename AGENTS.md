# Documentation Writing Guidelines

## Purpose
Write documentation that teaches readers how the bot works, why features exist, and how to use them in context.

## Writing style
- Write like a knowledgeable person explaining something to another person.
- Prefer flowing prose and connected explanations over lists of disconnected facts.
- Explain the reasoning, purpose, and context behind features.
- Use a natural, approachable, informative tone.
- Assume readers are intelligent but may be unfamiliar with the subject.
- Define technical terms when they first appear.
- Avoid robotic, repetitive, overly formal, or marketing-style language.
- Do not begin every section with a formulaic definition.
- Vary sentence structure and paragraph length naturally.

## Structure
- Introduce the topic before diving into implementation details.
- Explain what a feature does, why it exists, and when it is useful.
- Use examples to make abstract concepts concrete.
- Use headings to organize ideas, not to fragment every paragraph.
- Prefer prose for explanations and bullets for genuinely discrete items,
  procedures, options, or reference lists.
- Avoid turning every page into a glossary or checklist.

## Technical accuracy
- Verify explanations against the actual source code and current behavior.
- Never invent functionality, defaults, limitations, or examples.
- Distinguish intended behavior from implementation details.
- Link to related documentation where it helps the reader understand context.

## Editing existing documentation
- Preserve accurate existing explanations.
- Improve clarity and flow without rewriting everything unnecessarily.
- Match the established voice across the documentation.
- Check MDX syntax, links, and frontmatter before finishing.
