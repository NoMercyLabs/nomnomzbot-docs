## User surface

How to read the grants. A script call goes through `bot.call(key, ...)`; "an ungranted key is denied" (SdkRuntimeSurface.cs:571, JintScriptExecutor.cs:45-47). All grant keys are gated by the per-channel Custom Code feature toggle (`FeatureGate = "custom_code"`, ScriptCapabilityBroker.cs:35), which the owner turns on in "Settings -> Features" (broker comment, ScriptCapabilityBroker.cs:26-27; the exact dashboard label of that toggle is not checked in this slice). Tier is `low` or `tos` (ScriptCapabilityBroker.cs:37-81). A widget call runs "as the channel owner, within the owner's own permissions" (nnz-widget.d.ts:2127).

## Flows

1. Get the types in the editor (how the typed surface reaches a user). The server serves them as plain text at `GET /api/v1/sdk/types.d.ts` with `context` = `widget` or `script`; `script` is the default when `context` is missing (SdkController.cs:68-88,192-193). Optional `trigger` (an event response key or `command`) types `bot.getVar` to that trigger's keys (script only). Optional `script` (a script id) uses that script's own triggers. Optional `widget` types the widget's own settings. `trigger` and `script` together give 400 "Pass either a trigger or a script, not both." (SdkController.cs:93-94). Any signed-in caller with `sdk:read` on their own channel may read it (SdkController.cs:32-33,69). How the dashboard editor loads this is not in this slice.
2. Read the event list. `GET /api/v1/sdk/event-catalog?context=widget|script` returns one item per visible event: wire name, visibility, payload JSON Schema and a sample (SdkController.cs:170-190; SdkTypeEmitter.cs:136-151). Samples come from real Twitch fixtures run through the real translator, with a reflection fallback for internal events (TranslatedEventSamples.cs:24-34; ReflectionSampleGenerator.cs:20-29).
3. Write a chat-command script (derived from the signatures; not run). Create the script, set it to run from a command through the `run_code` action (`'run_code': { code_script_id: string; }`, nnz-widget.d.ts:1730-1732). Read the viewer with `bot.getVar('user.name')` (a key in ChatCommandVariableKeys.cs:34) and answer with `nnz.api.chat.reply(text)` (needs grant `chat.reply`). Use `console.log(...)` to see lines in the test run panel (SdkRuntimeSurface.cs:576-581).
4. Check a call failed. After a host call returns null or false, read `nnz.lastError`; it holds `{ code, message }` with one of six codes (SdkRuntimeSurface.cs:885-893) and is null after a success (CaptureScriptHostBridge.cs:55-56 comment; ScriptHostBridge.cs:126,147).
5. Run a pipeline action from a script. Call `nnz.api.actions.invoke('tts_synthesize', { text: 'hi' })`. The action type must be a string literal; the grant is per type (`actions.invoke:tts_synthesize`) (SdkRuntimeSurface.cs:911; ScriptCapabilityBroker.cs:83-93). The result has `success`, `output`, `error`, `variables`.
6. Read stream numbers in a script. `nnz.api.stats.stream({ metrics: ['followers', 'peakViewers'] })` returns the typed pick plus `stream`; it returns null when the channel has no such stream (SdkRuntimeSurface.cs:839-843).
