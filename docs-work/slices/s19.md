## Flows
1. A viewer types a built-in command (for example `!uptime`). The bot works out which reply case applies (a slot, for example `live` or `offline`). It then picks the text in this order: the channel's own text for that exact slot, the platform admin's text for the slot, a random line from the channel's tone, the built-in's neutral fallback. It fills the variables (for example `{uptime}`) and types the result in chat as the channel's one bot voice. (Builtin/IBuiltinResponseComposer.cs:19-24)
2. A streamer re-words a built-in reply. The dashboard lists reply groups and slots from the server. For each slot the streamer sees the current text, its source (`channel`, `platform` or `tone`), the default text, the tone variations and the variables with sample values. Saving a text sets the channel's own text for that slot. Resetting returns the slot to the default text. The shown labels come from `builtin.reply.*` keys whose English words are not in this slice. (Dtos/BuiltinReplyDtos.cs:28-65)
3. A streamer's own reply text is never tone-styled. Tone only changes text the system wrote. (BuiltinResponseSlots.cs:20)
4. A streamer changes the channel tone. Every built-in reply and every event response that follows the platform default changes wording on the next send. A text the streamer wrote does not change. If a tone has no line for a slot, the Informative line is used. (ToneTemplateCatalog.cs:33-49; Dtos/EventResponseDtos.cs:19-24)
5. A streamer creates a command. The streamer gives a Name, picks a Tier (`template`, `pipeline` or `code`), sets the permission floor, cooldowns and optional aliases, and fills the reply (TemplateResponse or TemplateResponses), a PipelineId or a CodeScriptId. After save the list shows UseCount, aliases and cooldowns. (Dtos/CommandDtos.cs:89-154)
6. A streamer resets a fun-command preset. The preview shows every field the reset writes back. The command's name and on/off state are not touched. (Dtos/CommandPresetDtos.cs:14-31)
7. A streamer adds a keyword auto-reply (chat trigger). Fields: Pattern, MatchType, CaseSensitive, IsEnabled, a Response or a bound pipeline or target, CooldownSeconds, MinPermissionLevel. A bound target or pipeline wins over the Response. (Dtos/ChatTriggerDtos.cs:38-78)
8. A streamer adds a timer. Fields: Name, Messages, IntervalMinutes, MinChatActivity, FireOnce, optional Target. After save the list shows the interval, the number of messages and when it last fired. (Dtos/TimerDtos.cs:42-89)
9. A streamer deletes a pipeline. Before the delete, the dashboard shows the counted commands, chat triggers, timers and event responses that use it. If the total is zero it must say that nothing else references it. (Dtos/PipelineDtos.cs:163-181)
10. A streamer opens a failed pipeline run. The detail view lists each step in order with Succeeded, DurationMs and ErrorMessage, so the failing step is visible. (Dtos/PipelineExecutionDtos.cs:27-48)
11. A viewer picks a TTS voice by chat. `!voice` alone lists the subcommands. `!voice <search>` sets the voice when one voice clearly matches, and lists matches when none is the clear pick. `!voice get <language>`, `!voice set <name>`, `!voice languages`, `!voice current`, `!voice roulette`, `!voice clear` also exist. (ToneTemplateCatalog.Community.cs:430-867)
12. A moderator handles a mass ban in a live channel. The bot posts a notice that a ban of N accounts waits. The broadcaster, a lead moderator or an editor types `!allow massban` to ban now or `!disallow massban` to stop it. With no answer, the bans run when the stream ends. Every tone uses the same plain text. (ToneTemplateCatalog.MassBan.cs:67-76)
