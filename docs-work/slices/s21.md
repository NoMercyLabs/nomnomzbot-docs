## Flows

1. Change the command prefix and basics (needs the action `setup:write`).
   1. Open Settings, then the sidebar entry "Bot basics".
   2. The page shows the section "Commands and language" (en.json:77) with fields "Command prefix", "Bot line marker", "Language", "Timezone", "Join chat automatically", "Keep commands and rewards on while offline", and "Viewer activity levels".
   3. Edit a field. The buttons "Save" and "Discard changes" (en.json:82-83) apply.
   4. Press "Save". On success the page shows "Basics saved." (en.json:80). If a rule fails it shows the server message (for example "Command prefix must be 1-5 non-whitespace characters").
   5. The new prefix works in chat at once, with no restart (IChannelService.cs:78-81).
   6. For viewer levels a wrong number shows "Use a whole number from 1 to 1,000,000." and a wrong order shows "Each step must be higher than the one before it." (en.json:125-126).

2. Delete a channel and bring it back (action `setup:write`).
   1. The user opens the delete step. The server first returns the preview: channel name, counts of what goes, outside effects, the restore window in days and the exact date after which data is gone (ChannelDeletePreviewDto.cs:41-47).
   2. The user types the channel name to arm the confirm button (ChannelDeletePreviewDto.cs:26-29 comment). Button text: not checked.
   3. The bot stops serving the channel at once. All rows stay for 30 days.
   4. Inside 30 days the user calls Restore. After the date the server fails with `CHANNEL_RESTORE_WINDOW_EXPIRED` (IChannelService.cs:141-145 ; ChannelService.cs:872-874).

3. Reset a channel to defaults.
   1. The preview shows counts by settings area. A reset cannot be undone and has no date (ChannelResetPreviewDto.cs:16-19).
   2. After confirm the configuration rows of those areas are removed.

4. Connect a bot account for one channel (own bot).
   1. The user opens Integrations and starts the bot device login for the channel.
   2. The server answers `NOT_ENTITLED` ("This channel's plan does not include its own bot account.") if the plan has no own bot (AuthService.cs:852-862).
   3. Otherwise it returns a user code and a link (DeviceCodeStartDto). The user approves it at twitch.tv/activate with the bot's own Twitch account.
   4. The client polls. On `authorized` a channel bot is stored for that channel only. The shared bot is untouched (IAuthService.cs:130-145).
   5. If no dedicated bot exists, the streamer's own account speaks in chat (IChannelTwitchBotResolver.cs:16-19).

5. Connect or disconnect an integration (action `integration:write`).
   1. Open Integrations. Each row has "Connect" or "Disconnect" (settings/integrations/i18n/en.json:38, 40).
   2. Connect calls `POST .../integrations/{provider}/connect` with a scope set key and a return URL. The server returns an authorize URL and a state. The user is sent to the provider, then back to the return URL (OAuthDtos.cs:19-26 ; IIntegrationOAuthService.cs:42-51).
   3. For Shopify the user must give the shop name (bare, or `name.myshopify.com`).
   4. Before a disconnect the page can show the blast radius: pipeline steps and supporter feeds that stop working (IIntegrationBlastRadiusService.cs:17-35).
   5. Disconnect revokes the token at the provider where the provider supports it, then marks the connection revoked. Repeating it is safe (IIntegrationOAuthService.cs:73-81).

6. Use media share as a moderator (action `media:moderate`).
   1. Open "Media share" from the sidebar (needs `media:read`).
   2. A viewer submission arrives in the section "Waiting for approval" (en.json:41 region). Buttons "Approve" or "Reject".
   3. Approved items move to "Up next". Buttons "Move up", "Move down", "Play now", "Skip".
   4. The player card has "Play", "Pause", skip, stop, volume and seek. If the overlay is not loaded in OBS the card says "The Media share browser source is not loaded in OBS, so nothing plays on stream." and offers "Set up in OBS".
   5. Reject or skip refunds the points the viewer paid (MediaShareService.cs:259, 284).

7. Set up media share (action `media:write`).
   1. In the settings card turn on "Accept media from viewers" (default off).
   2. Choose "Approve each item before it plays", "Allow Twitch clips", "Allow YouTube videos", "Twitch subscribers only", and the numbers "Longest item (seconds)", "Cost per item (points)", "Longest queue", "Wait between items per viewer (seconds)".
   3. Press "Save settings".

8. Set pronouns as a viewer (action `pronouns:self:write`).
   1. The viewer reads current pronouns (`GET pronouns/me`).
   2. The viewer sets a primary and an optional alt. ManualOverride true pins the choice. Sending 0 clears a field.
   3. Without the pin, the bot may overwrite the value from alejo.io, at most once per 24 hours per viewer.

9. Import from StreamElements (API only, no dashboard page found; action `commands:write`).
   1. Send the SE chatbot export JSON to `POST channels/{channelId}/import/streamelements`.
   2. The server creates commands, quotes and timers through the normal services (same validation and quota as hand-made ones).
   3. The reply is counts: imported and skipped per kind, plus warnings (ImportSummary.cs:19-30).
   4. Running the same file again imports nothing new.

10. Install a bundle (API only; no dashboard page found).
   1. Inspect the ZIP first: it returns manifest, capability list and issues. A bundle with issues cannot be imported (IBundleImportService.cs:26-29).
   2. Import with a conflict policy (Rename, Overwrite, Skip). Custom code lands disabled.
   3. List installed bundles. Uninstall shows a counted list of what goes, then removes exactly that.
