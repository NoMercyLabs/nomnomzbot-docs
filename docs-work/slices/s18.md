How to read the "Who may use it" column. The names come from `ActionDefinitionSeeder.cs`. "Mod" is level 10, "Vip" is 4, "Editor" is 30, "Broadcaster" is 40, "Everyone" is 0 (`ActionDefinitionSeeder.cs:42-54`). `MFloor(key, Mod, Vip)` means the action starts at Moderator and the broadcaster may lower it as far as VIP. `M(key, Mod)` means Moderator and it cannot go lower (`ActionDefinitionSeeder.cs:150-165`). `C(key)` is a community action open to Everyone (`ActionDefinitionSeeder.cs:552-554`). The word "moderator" here is the permission level, not a Twitch role check. How the ladder maps to Twitch roles was not checked.

## Flows

1. Turn on TTS and pick a voice (TTS page).
   1. Open "Text to speech" in the sidebar. You see the tabs "Overview", "Voices", "Rules", "Pronunciation", "Keys".
   2. In "Speaking", use the switch "Read messages aloud". The page header reads "Text to speech is on" or "Text to speech is off". (`en.json:5-6,128-131`)
   3. Open "Voices". Search with "Search voices" and narrow with "Language". Press "Play sample" to hear a voice. Click a row to make it the channel default ("Click a row to make it the channel default"). Use "Load more voices" for more. (`en.json:52-68`)
   4. In "Rules" set "Who may be heard", "Maximum characters", "Cooldown", "Skip bot messages", "Censor profanity", "Read usernames", "Moderators approve first", "Viewers pick their own voice" and "Minimum bits". Each shows "Default: ..." beside it. (`en.json:95-124,128-169`)
   5. To go back, press "Reset to defaults". The note says "Keys, voice and pronunciation stay."

2. Prove the OBS speaker works.
   1. Add the Audio overlay link to OBS. It is listed under the Required overlays on the OBS page (`en.json:49`; `WidgetsController.cs:147-173`).
   2. Run the overlay test (button label not checked). The bot says "This is a test of the text to speech overlay." through the real pipeline (`TtsConfigController.cs:93-132`).
   3. The settings page shows when the overlay last reported running (`TtsConfigController.cs:67-91`).

3. Use your own provider key.
   1. Open "Keys". Choose "Azure speech key" or "ElevenLabs key", paste the key, and for Azure set "Azure region" (placeholder "westeurope").
   2. Press "Save key". The page then shows "Key stored" and never shows the key again. To replace it, type a new one ("A key is stored. Type to replace it.").
   3. Set "Voice source" to "My own key". Press "Remove key" to go back to the platform setup. (`en.json:132-137,202-221`; `TtsConfigController.cs:256-299`)

4. Add a pronunciation rule.
   1. Open "Pronunciation", press "Add rule".
   2. Fill "Phrase" and "Say instead". Choose "Match": "Whole word, any case" or "Exact text".
   3. Press "Save rule". A repeat of the same phrase and match shows "A rule with this phrase and match already exists." (`en.json:175-190`)

5. Review held messages (when "Moderators approve first" is on).
   1. A moderator opens the approval queue and sees pending lines, newest first, 25 per page.
   2. "Approve" synthesizes it and plays it on the overlay. "Reject" discards it and nothing is spoken. (`TtsQueueController.cs:45-108`)

6. Add a voice trigger and start the listener.
   1. Open the voice triggers page and create a trigger (word, optional starting count, sticker; field labels not checked).
   2. Use the copy-link button for the listener link (`VoiceTriggersController.cs:45-62`).
   3. Open the link in a real Chrome tab, not an OBS source. Allow the microphone. The status chip shows "Listening".
   4. Speak. Each finished phrase appears in the list as "(checking...)", then "Matched "<word>" (count N)" or "(no trigger word)".
   5. Leave the tab open. Closing it stops voice triggers until you reopen it. (`VoiceListenerPageController.cs:89-97,133-155`)

7. Test an overlay widget without waiting for a real event.
   1. In the widget editor, pick an event type and fire the sample at one widget.
   2. The answer says `Delivered` true or false and `Attached` true or false. Delivered false means the widget does not listen for that event or is off. Attached false means no OBS source had it open. (`WidgetTestEventController.cs:112-134,167-169`)

8. Share a widget link safely (token rotation).
   1. Rotate the token for one widget. The result carries the old link, the new link and the date the old one stops working.
   2. Copy the new link into OBS before that date. Other widgets keep their links. (`WidgetsController.cs:523-550`)

9. Delete a widget or a webhook endpoint.
   1. Press delete. The dashboard must first ask for the counted impact and show it (`DestructiveAction(HasCountedBlastRadius = true)`).
   2. Confirm. The widget returns "no content"; the webhook endpoint stops receiving or sending. (`WidgetsController.cs:345-385`; `WebhooksController.cs:103-126,259-283`)

10. Set up a webhook.
    1. Inbound: create an endpoint, copy its ingest URL; rotate the token to retire an old URL. Creating needs the Editor level.
    2. Outbound: create an endpoint, pick event types from the catalogue, press test, read the delivery log. If an endpoint was switched off after failures, re-enable it first; a single-delivery retry is refused while it is disabled.
    3. The comment says an outbound endpoint needs an enabled row in the egress allowlist; that row's screen was not read. (`WebhooksController.cs:24-27,128-257`)

11. Connect VTube Studio.
    1. Save the connection (Broadcaster level).
    2. Press authorize. VTube Studio shows an Allow dialog. Click Allow within about 60 seconds.
    3. The token is stored and never shown. (`VtsController.cs:38-49,78-86`)

12. Fix a missing Twitch scope.
    1. Open the scope view; it shows each feature as granted or missing.
    2. Start the re-grant. The page shows a user code and a link. Approve on Twitch. The new grant includes the old scopes and the missing ones. (`TwitchDiagnosticsController.cs:100-141`)

13. A viewer picks their own voice.
    1. The viewer must have linked their account for the channel's platform. If not, the answer is 404: "Connect your <provider> account to pick a voice." (`TtsConfigController.cs:622-629`)
    2. If the channel turned self-service off, the answer is 403 FEATURE_DISABLED (stated in the comment at `TtsConfigController.cs:537-538`; enforced in `TtsConfigService`, not read in this slice).
    3. Chat command: `!voice` (`en.json:112`).
