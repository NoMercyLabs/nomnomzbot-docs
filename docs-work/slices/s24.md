## Flows
1. Turn the feature on (needed once per channel).
   1. Open Settings, then Features (label "Features"). Find "Custom Code" and switch it on. The feature is off by default (FeatureService.cs:51-56).
   2. If it is off, the Scripts page shows the bot's reason in the list area, not the empty text: "Custom code is not enabled for this channel. Enable it on the Features page." (CodeScriptsController.cs:273-276; ScriptsView.vue:14, 109-114). Not checked: the exact on-screen wording after `errorText` runs.
2. Create a script.
   1. Open "Scripts" in the sidebar (needs the author right).
   2. Press "New script". The dialog reads "It starts with a small example. It stays off until you switch it on."
   3. Type a name in "Name" (placeholder "My script"). Press "Create script".
   4. The dialog closes. The new script opens in the detail pane (the URL gets `?script=<id>`). The list shows it as "Never run" with no badge. The script is off.
   5. If the bot refuses, the dialog stays open and shows the reason.
3. Edit the code.
   1. Pick the script in the list, then press "Edit code" in the detail header.
   2. The full-window editor opens with the starter file and the typed `nnz` declarations. If the declarations cannot load, the editor shows "SDK types could not load. Type checking is off until you reopen this file." (shell/en.json:1209 area, `sdkTypesNotice`; flag set at ScriptDetail.vue:339).
   3. Edit, then press "Save & Compile" (or Ctrl+S). While it works the button reads "Compiling…".
   4. On success a new version is published and becomes the live version; the page behind reloads and the "Version" fact goes up. On a compile or validation error the editor shows the reason and nothing is saved (CodeScriptsController.cs:114-129; useScriptEditor.ts:54-66).
   5. Press "Close". If edits are unsaved, a dialog asks "Keep editing" or "Discard changes".
4. Switch the script on.
   1. Use the switch in the row or in the detail header ("On" / "Off"). It moves at once.
   2. The script does not run by itself. It runs only when a pipeline step uses it (controller comment: "No endpoint runs a script — execution is the run_code pipeline action", CodeScriptsController.cs:31-33). The detail section "Runs from" says "Nothing runs this script yet. Add it to a pipeline step." until a pipeline uses it.
5. Test the script.
   1. Open the script. In the "Test" card read "A test run is a dry run. Nothing it does reaches chat."
   2. If the code reads a pipeline variable with `bot.getVar('name')`, pick an event in "Event to test with (only events this script reads from)". Otherwise there is no picker and the test runs with "No event".
   3. Press "Run test".
   4. The card shows "Worked, {ms} ms" or "Failed, {ms} ms", an error text if any, and a "Timeline" with the kinds Started, Chat, Effect, Console, Error. A "Runs" side panel (titled "This session") appears and lists the run.
   5. If the run failed, the dialog "The run failed" opens by itself with the error, the place, the steps, "What it did before it stopped" and the "Log".
   6. If you press Run test too often, the button turns off and the card says "Too many tests, wait a moment" for the Retry-After seconds (or 10).
   7. Important: the test uses the saved, live version, not what is open in an unsaved editor (see Traps).
6. Read a failed run later.
   1. A script whose last real run failed shows badge "Failed" in the list and the error text in the detail. The tab "Failed" lists such scripts.
   2. The list "This session" holds only test runs of this visit; a reload clears it.
7. Duplicate.
   1. Open the script, press "Duplicate" in the footer. A new script "{name} copy" opens. It has the same code, and it is switched off.
8. Delete.
   1. Open the script, press "Delete". The bot lists what uses it (pipelines, pipeline steps, commands, ...), or "Nothing else uses this script."
   2. Confirm with "Delete script". The list reloads and the detail closes. Cancel does nothing.
9. Versions (what is and is not on this page).
   1. The detail shows the number of the live version under "Version".
   2. The code editor publishes a new version on every successful "Save & Compile".
   3. There is no versions list, rollback or version delete on this page. See Traps.
