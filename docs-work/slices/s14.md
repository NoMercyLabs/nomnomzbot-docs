## Flows

1. Connect an integration or bot with a popup (Spotify, Discord, YouTube, custom bot)
   1. The streamer presses the connect button on the dashboard. A popup opens at the provider.
   2. The provider sends the browser back to the server. The server redirects to `/oauth-relay?...` (for a channel bot: `/oauth-relay?custom_bot_connected=true`, AuthController.cs:536).
   3. The popup shows "Connected" with the text "You can close this window." and a button "Close this window". It tells the dashboard tab, then closes after 0.9 s.
   4. On failure the popup shows "That did not work" and "This window closes. The dashboard shows what went wrong." and closes after 1.5 s.
   5. If the browser will not close the window, the popup text changes to "You can close this window now." (OAuthRelayController.cs:162-168).

2. Sign in as a streamer on the web (redirect flow)
   1. The sign-in screen sends the browser to `/api/v1/auth/twitch?client=web`. The server creates a one time state and redirects to Twitch.
   2. The streamer approves on Twitch. Twitch returns to `/api/v1/auth/twitch/callback`.
   3. The server sets the `nnz_refresh_token` cookie and the `nnz_session` marker and redirects to `/app` (or the saved return path) with the access token in the address fragment.
   4. A bad or reused state shows the plain text "Invalid or expired OAuth state."

3. Sign in with a device code (no secret)
   1. The client calls `POST /auth/twitch/device`. It receives a short code and the twitch.tv/activate address to show.
   2. The streamer opens twitch.tv/activate and enters the code.
   3. The client polls `POST /auth/twitch/device/poll`. The status is pending or slow_down until approved. After approval the session opens. For web the refresh token goes into the cookie and is removed from the body.

4. Link a second account (Kick, X, YouTube)
   1. In account settings the streamer starts a link. Kick and X return an authorize address. YouTube returns a device code and address.
   2. Kick and X: the browser returns to `/api/v1/auth/{provider}/callback`. The web client lands back on the page it started from with `#linked={provider}` or `#link_error={code}` (AuthController.cs:1142-1153).
   3. YouTube: the client polls `.../link/poll` until the status is authorized.
   4. Unlink a non-primary account, or make an account primary, from the same list. The last account and the primary account cannot be removed (409).

5. Pair a Stream Deck (code made in the dashboard)
   1. In the dashboard the streamer asks for a pairing code (`automation:tokens:write`). The code is single use and lasts 5 minutes.
   2. The device sends the code to `/automation/v1/pair`. It receives the token secret once and the bot address.
   3. The device then shows in the normal token list. Revoking it there unpairs it.

6. Pair a Stream Deck (device starts)
   1. The device calls `/automation/v1/pair/device/init` and shows a short code and address.
   2. The streamer opens that address. The page title is "Approve device — NomNomzBot". If they are not logged in in this browser the button reads "Log in first" and the text says "Open your NomNomzBot dashboard in this browser, log in, then reload this page."
   3. They press "Approve". The page then reads "Device approved" and "You can close this tab and return to your Stream Deck."
   4. The device polls `/automation/v1/pair/device/poll` and receives its token.

7. Add an overlay to OBS
   1. The dashboard hands out the address `/overlay?widgetId={id}&token={overlayToken}`. The streamer adds it as a browser source in OBS.
   2. The page asks for a ticket (`POST /overlay/ticket`), then opens the live connection. Widgets show events and settings changes live.
   3. If the token is wrong the source shows a red box: "Widget token invalid or revoked — reconnect from the dashboard".
   4. If the widget id or token is missing or unknown the source shows a small dark box with one of the messages in the table above.

8. Add the OBS bridge
   1. The dashboard hands out `/obs-bridge?token={BridgeToken}`. The streamer adds it as a browser source inside OBS.
   2. The page opens the local OBS WebSocket at `127.0.0.1` on the channel's saved port (4455 until it arrives). If OBS has a password the bot sends the saved password over its private link.
   3. VTube Studio runs through the same page. On first use VTube Studio asks the streamer to approve the plugin "NomNomzBot". The token is stored in the browser source's local storage.

9. Change a built-in command
   1. List built-ins (`commands:read`). Open one.
   2. Change cooldown, per user cooldown, minimum permission, enabled, or "speak with TTS" (`commands:write`).
   3. Change or reset the wording of a single reply slot. The reply catalogue shows the text that is live now and which layer it comes from.
   4. Reset the whole built-in to defaults with one delete call.

10. Upload a media asset for widgets
   1. Upload a file (multipart, 8 MB max). A file with the same name replaces the old one and keeps the same address.
   2. Before delete, the dashboard asks for the blast radius and shows what depends on the asset. Then it deletes.
