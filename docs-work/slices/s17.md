## Flows

These are API-level flows. The dashboard labels for the buttons are in the dashboard slices.

1. First-run setup (self-host). (1) GET `system/status`: the user sees whether onboarding is complete and the checks. (2) GET `system/setup/wizard`: the user sees ordered steps and the exact redirect URI to register at Twitch. (3) Either PUT `setup/credentials/twitch` with a client id (secret optional), or POST `setup/credentials/twitch/use-shared`. (4) Optional: PUT `setup/credentials/spotify`, `discord`, `youtube`, `kick`. (5) POST `setup/complete`. From now on these routes need the `admin` role. SystemController.cs:105-480.
2. Build and test a pipeline. (1) GET `pipelines/actions` to fill the palette. (2) POST `pipelines/validate` as the user edits. (3) POST `pipelines` to save (201). (4) POST `pipelines/{id}/test-run` with sample variables: the user sees what each step would do; nothing is sent. (5) When something fails later, GET `pipeline-executions?failuresOnly=true` then `.../{id}` for the per-step logs. PipelinesController.cs:176-294; PipelineExecutionsController.cs:41-78.
3. Delete a pipeline, reward, pick list, sound clip or jar. (1) GET the item's `blast-radius`. (2) The user sees the counted dependents. (3) DELETE the item. Controllers comment that the dashboard must show step 2 before step 3; the server does not force the order (not checked in the service). PipelinesController.cs:222-256; RewardsController.cs:307-347; PickListsController.cs:154-182; SoundClipsController.cs:195-235; SavingsJarsController.cs:88-117.
4. Handle a channel point redemption. (1) GET `rewards/redemptions?status=unfulfilled`. (2) POST `.../{id}/fulfill` (Twitch FULFILLED) or `.../{id}/refund` (Twitch CANCELED, points returned). RewardsController.cs:97-210.
5. Run a "streamer does X for Y" countdown. (1) GET `rewards/redemption-timers`: active first, then recent finished; remaining seconds are computed at response time. (2) Pause, resume, complete (also fulfills on Twitch) or cancel (no fulfill, no refund). RewardsController.cs:138-192.
6. Switch on spam defense carefully. (1) GET `spam-defense/policy`. (2) GET `detections` over a week: during dry run it lists what the system would have done (comment). (3) PUT `policy` (Broadcaster) to change weights or turn enforcement on. (4) Overturn wrong verdicts, or restore a follow-bot batch. SpamDefenseController.cs:64-249.
7. Lock down chat by hand. (1) POST `spam-defense/lockdown` with a reason and at least one control (LeadModerator). (2) GET `lockdown` shows the open window. (3) POST `lockdown/end` puts the room back. SpamDefenseController.cs:255-322.
8. Connect OBS. (1) PUT `obs/connection` (Broadcaster). (2) For bridge mode, GET `obs/bridge/setup` and install the URL it returns in OBS. (3) GET `obs/probe` for the real connected or error answer. (4) GET `obs/scenes` and the other reads fill the control panel. Rotate the bridge token if the URL leaks. ObsController.cs:155-181, 537-605.
9. Upload a sound clip. (1) POST `sound-clips` as multipart with Name and File (Mod by default). (2) POST `sound-clips/{id}/preview` plays it on the overlay. (3) POST `sound-clips/stop` stops playback; 409 if no overlay is connected. SoundClipsController.cs:116-273.
10. Give a helper power. (1) PUT `roles` with a user and role (Broadcaster). (2) Or POST `permits/role` or `permits/capability` with optional `ExpiresAt` and `Reason` for a time-limited grant. (3) GET `permits` lists the active grants; DELETE `permits/{userId}` revokes. RolesController.cs:67-90; PermitsController.cs:49-133.
11. Change title, game or tags. PATCH `stream/title`, `stream/game` or `stream/tags`, or PUT `stream` for several at once. The game is resolved to the platform's category name. StreamController.cs:223-394.
12. A viewer requests a song. (1) Open the public page (token link or by-channel name link). (2) POST a request with a query and an optional name. (3) The viewer sees "Song added to the queue." or a 404/409 message. PublicSongRequestController.cs:37-108.
13. Install a platform template. (1) GET `platform-templates?kind=timer` (or another kind). (2) POST `.../{definitionId}/install`. (3) Later, GET `.../updates?kind=` and POST `.../copies/{rowId}/update`; this replaces the channel's own edits to that copy. PlatformTemplatesController.cs:40-124.
