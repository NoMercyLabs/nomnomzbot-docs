## Flows

These files are contracts, not screens. The steps below follow the contracts only. The exact button labels are not in these files; they live in dashboard i18n files this slice did not open.

1. Ban or time out from the dashboard. The operator picks a user and a scope. `this_channel` bans (or times out when a duration is sent). `all_moderated` bans permanently in your own channel and every channel Twitch lists you as moderator for. The result reports Attempted, Succeeded and one row per channel with an error text where a ban failed (NetworkBanDtos.cs:14-44; IOperatorNetworkBanService.cs:16-26).
2. Mass ban a list. The moderator sends accounts (numeric Twitch ids, optional reason), may name attacked channels and excluded channels, and may preview first. The preview shows each channel's status. The result shows per channel `banning`, `awaiting_approval`, `held_until_offline`, `excluded` or `not_opted_in`. Live channels with the bot ask their chat; the broadcaster, a lead moderator or an editor types `!allow massban` to run now or `!disallow massban` to stop. If nobody answers, the bans run when the stream ends. The progress list then shows counts and failed or retrying accounts (IMassBanConsentService.cs:16-25, 62-98; MassBanDtos.cs:19-65).
3. Resolve a held AutoMod message. The moderator opens the review queue (status pending), picks approve or deny. On deny the moderator may add a follow-up: none, timeout with seconds, or ban, with a reason. If Twitch accepts the deny but the follow-up fails, the message stays denied and the moderator sees the follow-up error (ModerationQueueDtos.cs:29-57; IModerationQueueService.cs:77-91).
4. Approve an unban request. The moderator opens unban requests by status, picks a request, chooses approve and confirms. Approval without `Confirm: true` is rejected before Twitch is called. Deny needs no confirmation and may carry a note the viewer sees (ModerationDtos.cs:234-245; IModerationService.cs:169-183).
5. Set up the escalation ladder. The owner or lead moderator sets enabled, offense window hours, rungs and the one-click timeout length, then saves the whole policy at once. A refused save names the failing field (`offenseWindowHours`, `defaultTimeoutSeconds`, `ladder`, or `ladder[2].timeoutSeconds`). "Reset" for a viewer clears their tally (EscalationDtos.cs:78-85; EscalationPolicyViolation.cs:16-31; IModerationEscalationService.cs:44-56).
6. Request a song. A viewer sends a link or a search phrase. The bot tries a link or id first, then falls back to search. A request can be refused for these reasons the code names: requests disabled (`SR_DISABLED`), not allowed for this source, track blocked (`TRACK_BLOCKED`), no provider active (`SERVICE_UNAVAILABLE`), nothing found (`NOT_FOUND`), and limits (length, queue size, per-viewer cap). A moderator or the broadcaster can then admit the refused request with `!permit` within 15 minutes; the block list and the duplicate check still apply (IMusicService.cs:83-118).
7. Change the song order. A moderator drags a song to a new position (zero-based) or chooses "play this one next". Banning a queued track blocks it for future requests and removes it from the queue (IMusicService.cs:221-257; MusicQueueDtos.cs:26-30).
8. Connect OBS. The owner picks mode `direct` or `bridge`, host, port and password, then enables the connection. A probe tells the real state: it reports Connected plus an error code (`OBS_NOT_CONNECTED`, `OBS_DISABLED`, `OBS_BRIDGE_OFFLINE`, `OBS_WRONG_MODE`) (ObsConnectionDtos.cs:54-90; IObsConnectionService.cs:22-46).
9. Dismiss an action-required item. The streamer opens the inbox, reads title and message, follows the link to the fixing page or dismisses the item. A new occurrence of the same problem (new token failure, new held message) shows again (ActionRequiredItemDto.cs:14-50; IActionRequiredInboxService.cs:29-40).
10. Take control of an external reward. The dashboard shows an externally created reward as read-only. "Take control" recreates an equivalent reward under the bot's own Twitch client and points the same local row at it, so settings carry over. If Twitch's title-uniqueness check blocks it, the reward shows a pending migration and a "Finalize migration" action once the owner renames or deletes the original on Twitch (IRewardService.cs:133-144; RewardDtos.cs:63-67).
