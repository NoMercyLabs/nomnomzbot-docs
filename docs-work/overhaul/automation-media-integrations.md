# Automation, overlays, music, audio and integrations

Author audit: 21 of 21 assigned articles read, checked against current implementation and edited. Independent reader review and combined documentation build belong to the lead's final pass. No product code, live settings, credentials or running bot were changed.

The current user prompt is the editorial authority. Atlas supplied only an evidence and validation workflow. Its fixed page shape, sentence caps, pilot-matching requirement and permission to omit broken controls were not used as editorial rules.

## What changed for readers

The everyday path now starts with a useful result: a welcome response, rotating reminder, reward reaction, supplied OBS source, first song, first spoken reply, chat sound or approved video. Reference tables remain available after that explanation. Code editing is optional in the overlay guides. The HTTP read-aloud article explicitly addresses developers and keeps its existing route; the lead is moving its navigation entry out of Voice and sound.

The pass corrected source drift rather than only adding introductions. The required sources live on OBS, speech plays through TTS caption, Spotify can use a shared app and an existing active device, testing and replaying responses can run real pipeline actions, and ordinary Twitch clip links can enter media share silently. Those distinctions change what readers do during setup.

## Current product gaps exposed by this audit

1. Required Alerts and Music Player settings cannot be reached in the current dashboard. `OverlaysView.vue:64-70` excludes required sources; `RequiredOverlaysPanel.vue:103-145` renders only source setup actions, and `ObsSetupAction.vue:165-190` is a connection/size/audio dialog, not settings. This also makes the old voice-trigger sticker setup unusable from the supplied Alerts source. The guides now state that boundary rather than send readers to a missing editor.
2. Spotify browser-audio permission has no current dashboard request path. `dashboard/src/api/integrations.ts:37-44` requests playback+library; `OAuthProviderRegistry.cs:90` defines a separate streaming set; `SpotifyMusicProvider.cs:572-581` refuses an embedded token without streaming. The player tells the user to reconnect, but the ordinary reconnect does not request that set. The guides preserve active-device playback and explain the gap.
3. Channel points has no New reward control, although duplication and server creation exist. The guide begins with an existing editable reward and documents duplication. The pre-existing Not on Twitch limit-drop and misleading Only lands in the queue issues remain; accurate descriptions were preserved.
4. Event-response Test describes nothing granted/counted, but a bound pipeline can run economy or other actions for real. The same response replay path can also execute attached actions. The old blanket no-side-effects guarantee has been removed. This is a presentation/controller wording gap in the product, not an application change in this task.
5. YouTube disconnect impact includes every music pipeline even though music playback does not require the channel sign-in (`IntegrationBlastRadiusService.cs:80-81`). The guide now states the actual dependency instead of repeating the misleading conclusion.
6. Required-source catalog includes the Stage source but OBS required-source English labels have no corresponding stage entry. The lead was notified for the overall action inventory. No invented name or setup control was added here.
7. The independent review found three visible TTS controls missing from the old reference. **Read usernames** and **Skip bot messages** are stored but not consulted by the speech dispatcher. **Moderators approve first** does hold speech, including paid reward/pipeline requests, but the dashboard has no queue review screen. The article now includes the controls, defaults, actual behavior, first-setup guidance and silent-speech troubleshooting. This is a documented UI/runtime boundary, not a product fix.
