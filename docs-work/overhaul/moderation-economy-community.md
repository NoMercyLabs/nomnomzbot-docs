## Source corrections that matter

- The historical giveaway verdict said Entries per viewer above 1 did nothing and announcement prizes posted nothing. Current `GiveawayService.cs:354-427` and `GiveawayFulfillment.cs:93-176` implement both, including actual-winner pot division. The revised guide now matches this behavior.
- `CatalogService.cs:467-538` now invokes the item's full binding target, including a pipeline. The old store article described that binding as a no-op.
- `EconomyLeaderboardService.cs:371-445` ranks jar contributors. It uses contributions for all selected metrics, which the guide now states.
- `ChatFilterExecutionHandler.cs:86-87` always skips broadcaster/moderators before the exemption setting. The previous troubleshooting advice could never work. Its escalation path also falls back to a timeout when the ladder is off.
- `ChannelAnalyticsService.cs:464-477` filters chat by channel and time, with no live-only condition. The old article's claim that chat happens only while live was removed.
- `chatDisplay.ts:54-59` and `ChatDisplayPanel.vue:80-96` expose first-message/account-age hints missing from the old article.
- Moderator notes, bot standing, suspicious-user flags, permits/data and personal voice controls were implemented but only named or omitted in the People article. They now have usable explanations and flows.
- The capitals matcher in `AutoModerationHandler.cs:145-177` has minimum-letter/minimum-length checks and interprets threshold 1 as a ratio of 100 percent. The article preserves the UI's allowed range while explaining that exception.
- Giveaway's Least standing level control is a number input, so optional reference now gives its actual community-standing values (0/2/4/6/10) from `AuthorizationLadder.cs:54-64`. This intentionally overrides the old editorial convention hiding numeric levels, which left that user-visible field unexplained.
- Giveaway claims are acknowledgments, not deferred fulfillment: `GiveawayService.cs:513-545` fulfills at draw and `GiveawayClaimSweepWorker.cs:87-104` changes an unclaimed winner's status without clawing the prize back. Redrawing fulfills another winner without reclaiming the earlier prize. The pot uses current saved entry cost, so the article explains the consequence of editing it after collecting entries.

## Remaining product limitations

These are documented boundaries, not application changes made by this task:

- Store purchases/refunds have API behavior but no ordinary viewer dashboard purchase flow.
- The currency WatchTime batch service has no automatic caller, and the gift-subscription source has no payout event handler. Seconds per payout alone has no cap effect.
- The savings-jar dashboard cannot accept an invitation, withdraw or deposit directly, and it does not reveal a channel ID for the invitation field. The article directs readers to the operator for that ID and identifies the pipeline contribution entry point without claiming a complete viewer UI.
- Only incoming shared-chat bans have federation enforcement; outgoing Share and the other sharing categories remain stored choices.
- Viewer report submission and additional account linking do not have dashboard controls.
- Giveaway age confirmation also lacks a viewer form; the age gate needs an integration to record consent before keyword/pipeline entries can pass it.
- Games and four viewer screens still route to Coming soon.
- Spam-defense settings marked Not yet active stay incomplete. Its alphabet label names established viewers while enforcement uses Regular.
- Trust calculation uses only a subset of the policy fields in the moderation projection, and heat threshold/automatic-timeout controls are not exposed by these settings views.
- Saved raid rules do not have a ranked-target UI on Stream.
