## Source-backed retained behavior

- `!play` default Moderator, 0 shared cooldown and inherited 0 personal cooldown: `MediaShare/Builtins/PlayBuiltin.cs:43-94`, `Application/Commands/Builtin/IBuiltinCommand.cs:25-32`. Args take precedence over Twitch reply-parent text; the executing caller is the submitted requester. It submits Approved rather than interrupting an already playing item. `!media` bypasses approval at effective level >=10. Both still call SubmitAsync's source, duration, eligibility, cooldown, queue and cost checks (`MediaShare/MediaShareService.cs:57-207`).
- Passive clip submission and Submit media do not set ApproveWithoutReview; the documented distinction is correct (`Chat/EventHandlers/ChatMessageHandler.cs:1518-1541`, `MediaShare/PipelineActions/SubmitMediaAction.cs:57-93`).
- Auto-start requires Approved status, no item in Playing, an enabled system media-share widget and attached presence (`MediaShare/Playback/MediaShareAutoStartHandler.cs:39-84`). This is attached-widget proof, not proof that OBS audio is audible.
- History replay, Play now and removal were traced through `MediaShare/MediaShareService.cs:239-359`, `MediaShare/Playback/MediaSharePlaybackService.cs:207-278` and `dashboard/src/views/dashboard/media-share/components/MediaShareQueueRow.vue`. Replay queues a played/skipped item first without charging; current playback continues. Play now skips/refunds the old current item and loads the selected item, including the guard for a replay already auto-started. Removing a finished item marks Rejected without a new refund. Rejected items have no replay controls.
- Sync waits only after Dispatched, for clamp(DurationMs,0,60000)+250ms; QueuedForApproval gets no duration wait (`Tts/PipelineActions/PlayTtsAction.cs:227-276`). This is a timed estimate, not a browser playback acknowledgment.
- Scene reserve defaults/clamp, output token, release and in-memory timeout match `Tts/PipelineActions/SceneReserveAction.cs:30-68`, `SceneReleaseAction.cs:33-60`, and `Tts/TtsSceneReservation.cs:23-97`. `SetVariableAction.cs:25-51` permits an empty Value and declares the Name. The usual TTS checks run before the reservation wait (`Tts/TtsDispatchService.cs:292-447,607-625`). Existing audio is not cancelled by reserve.
- The nine new action rows were compared with `Identity/PipelineActions/WhitelistActions.cs`, `Music/PipelineActions/SongQueueOpenCloseActions.cs`, `Music/PipelineActions/SongClearRequesterAction.cs`, `Tts/PipelineActions/SceneReserveAction.cs`, `SceneReleaseAction.cs`, and `TtsVoiceAssignmentActions.cs`. Whitelist/unwhitelist do their own >=40 invoker check, and permitted manual standings are subscriber/vip/artist/moderator. Queue intake open/close changes RequestsOpen (`Music/SongRequestIntakeService.cs:27-75`) without a music-stop call.
