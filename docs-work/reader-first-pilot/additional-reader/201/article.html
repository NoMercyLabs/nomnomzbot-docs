Chat commands let viewers ask for information or start an activity without waiting for you to notice the message. A schedule command can answer a question you hear every stream; a welcome command can greet the person who used it. You create both on the Commands page in the dashboard. Have the bot running, sign in, and select your connected channel. A working Twitch chat connection is needed for the first reply and test below.

Each command connects a trigger to a response. With the usual ! prefix, a command named schedule runs when someone types !schedule in chat. The bot checks whether that person may use it and whether it is cooling down, then sends your reply or runs the actions you chose.

If you have not tested the bot yet, Your first command takes you through one plain reply. Here you can build on that result, choose different responses, and find the exact trigger and editor options.

System commandsThe bot’s own commands, on Built-in commands.

Who can use this page

By default, a Moderator, Lead moderator, Editor or Broadcaster may open the page and change commands. The broadcaster can raise the access requirement. The roles are explained on Permissions.

The Broadcaster may also let a VIP open the page. This is set on the Permissions settings page, in the Commands area of the Actions tab. A VIP then sees the list only.

For a VIP, New command shows “You can view this, but your role cannot change it.” The System commands tab shows only to someone who may change commands.

Make a useful reply

For a schedule command, begin with a reply you can read back exactly as written. You can add changing information and more advanced actions after confirming that the simple version works.

  1. Open Commands in the sidebar and choose New command. The New command dialog opens.
  2. Type schedule in Name. With the default prefix, viewers use !schedule.
  3. Leave What it does at Sends a reply, and enter your own stream times in Reply. For example: I stream on Tuesdays and Thursdays at 19:00 Amsterdam time.
  4. Keep Send the reply to at Twitch chat, Prefix at Channel default and Match at Starts with.
  5. Choose Create command. The dialog closes and the new command opens in the editor, switched on.

Type !schedule in your channel’s Twitch chat as the broadcaster or a platform moderator. If your channel uses a prefix other than !, type that instead. The bot posts the reply you saved; those roles can test commands even while the stream is offline. When you edit the times later, choose Save changes before trying the command again.

Choose a different response

A text reply is enough for information such as a schedule or a community link. Use a random reply when you want variety, or a pipeline when the response needs several actions. Scripts are an optional route for people who want to write code.

What it doesThe field to fill in
Sends a replyReply: the line the bot sends.
Sends a random replyReply 1, Reply 2 and so on: one line in each box.
Runs a pipelinePipeline: the pipeline to run.
Runs a code scriptScript: a script from the Scripts page. See Scripts (Draft).

When the list is empty, the page shows “No commands yet.” Its Make the first command button opens the same dialog.

Rules for the name

The dialog cleans the name before it sends it:

  • It removes spaces at the ends.
  • It drops all leading ! characters.
  • It makes the name lowercase, so !Hello becomes hello.
RuleWhat happens
The name is emptyThe dialog shows “Give the command a name.”
The name has whitespace inside itThe bot refuses it. A name with whitespace can never match one chat word.
The name is only the prefixThe bot refuses it. The prefix is added for you when the command runs.
Another channel command has the same nameThe bot refuses it. Names are compared without letter case.
The name is longer than 100 charactersThe bot refuses it.

When the bot refuses, the dialog stays open with the reason in red. Nothing is made.

A reply goes to Twitch chat by default, in the channel’s one bot voice. Send the reply to in the creation dialog or editor can send it elsewhere for text and random replies (see Edit a command).

Write a reply

A reply can combine your own words with helpers, which insert information when the command runs. For example, this reply stays useful when you switch games:

Welcome! Today we play {stream.game}.

When the stream plays a game called Example Game, chat sees “Welcome! Today we play Example Game.”

The reply box holds up to 500 characters. A helper the bot does not know shows “Not a known helper here:” under the box, with the unknown names. The full list is on Variables and templates.

Write random replies

For Random reply, the bot picks one line from the list each time chat uses the command.

  1. With Reaction set to Random reply, choose Edit replies in the editor. The Random replies dialog opens: “One reply per line. The bot picks one of them each time.”
  2. Type each line in its own box: Reply 1, Reply 2 and so on. Add a reply adds a box.
  3. Choose Use these replies. The editor shows the count, for example “3 replies”.
  4. Choose Save changes. The unsaved count leaves the footer and Save changes turns off.

The X button beside a box removes it. When one box is left, X is off.

A list that many commands share is a pick list.

Start from another command’s replies

The Random replies dialog lists your other random-reply commands under Or start from a list you already have. Choose Use the replies of !name to copy that list into this command. A later change to one command does not change the other.

Triggers

A trigger is the message that runs the command. It has two parts: the Prefix and the Match. Both are in the New command dialog and in the editor’s Trigger and cooldowns group.

Prefix

The prefix is the text chat types before the name. The channel prefix is Command prefix on the Bot basics settings page (see Bot basics and personality).

ChoiceChat types
Channel defaultThe channel prefix and the name. The prefix is ! when the channel has set none. This is the default.
CustomYour own prefix and the name. Type the prefix in Custom prefix, up to 8 characters.
NoneThe name only, with no prefix.

The Custom prefix needs text in Custom prefix.

Match

The match says how a chat message must look to run the command. Letter case never matters.

ChoiceThe command runs when the message
Starts withstarts with the prefix and the name, followed by whitespace or nothing. This is the default. Text after the name goes to the command.
Exactis the prefix and the name, and nothing else.
Containsholds the prefix and the name as a whole word anywhere. A command named cat with no prefix does not run on “category”.
Regexfits your pattern in Regex pattern. A regex is a text pattern. It is tested against the message text; choosing Regex does not require a match of the entire message.

Regex needs a pattern. If the custom prefix or the pattern is empty, Create command shows “Fill in the custom prefix or the regex pattern you picked.” It makes nothing. In the editor, Save changes stays off.

Edit a command

  1. Choose the command in the list. The editor opens beside the list, with the command name at the top.
  2. Change the fields you want. The footer counts them, for example “2 unsaved changes”.
  3. Choose Save changes. The count leaves the footer and Save changes turns off.

Discard in the footer puts every field back as it was saved. If the bot refuses the change, red text names the reason. Your edits stay in the form.

Send the reply to and Read it aloud show only for a text or random reply. For these replies, Read it aloud queues speech only after the reply is successfully sent to chat. Choosing Chat overlay or Nowhere therefore does not speak the reply, even with that switch on. Speech also needs the channel’s text-to-speech setup to be ready. A pipeline or a script sends and speaks through its own steps. Cooldowns are explained on Cooldowns and permissions.

Reset a command to its preset

A preset is a ready-made command that the bot added to the channel. A command that came from a preset has a Reset to preset button in the footer. The dialog lists the settings that go back to the preset: “Your edits to them are lost.”

When nothing differs, it says “This command already matches its preset. Resetting changes nothing.” This restores a channel command’s preset; system commands have their own reset controls.

Switch a command on or off

Each row in the list has a switch. The editor has the same switch, Enabled, at the top. Both save at once, with no Save changes. Switching a command off can be refused while something else still runs it; move or remove those uses first, as for deletion below.

A command that is off stays in the list, marked Off. It answers nobody.

Copy a command

  1. Open the command in the list.
  2. Choose Duplicate in the footer. A copy named after the command with -copy at the end opens in the editor, for example !hello-copy.

The copy has most of the command’s saved settings, including Read it aloud. Speech still needs successful chat delivery and a ready text-to-speech setup. It does not keep aliases, which are additional names for the original command, or its reply destination and enabled state. The copy’s reply goes to Twitch chat. Choosing a different destination before testing is optional; switching the copy on is required.

The copy starts switched off. It has no Reset to preset button.

If a command with the copy’s name already exists, the bot refuses the copy. The editor shows the reason.

Delete a command

  1. Open the command in the list.
  2. Choose Delete in the footer. The dialog asks “Delete !name?”: “The command is removed for good. Chat can no longer use it.”
  3. Choose Delete command. The editor closes and the command leaves the list.

When something else still runs the command, the dialog does not open. The editor shows one line that names each kind of item, its count and up to five names. For two timers, it reads “Still used by 2 timers: …. Move or remove these first, then delete the command.”

Kind in the lineSidebar page

An other places line can include pending scheduled tasks that run the command. Those uses also block deletion or switching the command off; resolve them before retrying.

Commands that repeat a system command

A channel command can have the same name as one of the bot’s system commands. The list marks it Repeats !name.

A line above the list counts these copies. When the channel command’s trigger matches, it answers in chat instead of the ordinary system command.

!permit, !unpermit, !mydata, !gdpr and !forgetme are the exception. They always answer as the system command.

Move copies to system on that line asks you to confirm with Remove copies. Then every copy is removed for good. The ordinary system command’s saved enabled state, access requirement and cooldowns still apply; removing a copy alone does not guarantee an answer in chat.

Troubleshooting

When something is not right

The command does nothing in chat. Check these, in order:

  1. The switch in the list. A command that is Off answers nobody.
  2. Who can use it. The viewer’s role must be at least the role chosen under Who can use it.
  3. The prefix and the match. They must fit the message chat typed (see Triggers).
  4. Send the reply to. Chat overlay and Nowhere send nothing to Twitch chat.
  5. The Chat cooldown and the Per-person cooldown. A cooldown holds viewers, not the broadcaster or moderators.
  6. Whether you are offline. Viewers’ commands are ignored unless Keep commands and rewards on while offline is on in Bot basics. The broadcaster and moderators can still test them.
