## Reader, task and prerequisites

Reader: a streamer or moderator who can use the dashboard and wants a dependable channel command, with the editor reference available afterward. Main question: “How do I make and test a schedule reply, then change its trigger or response?” Success: create an enabled `schedule` text command, obtain the saved reply in connected channel chat, edit it and save the change.

Prerequisites: a running bot, signed-in selected channel, permission to read and write commands, and a working channel/chat connection for the delivery test. Default command management floor is Moderator (including higher roles); the broadcaster can raise the action requirement. VIP read access can be granted but does not allow editing. The example assumes channel prefix `!`; otherwise substitute the actual prefix. A broadcaster or platform moderator can test offline. Ordinary viewers additionally need live status or the channel’s offline opt-in, sufficient command access and clear cooldowns. Pipelines/scripts and TTS are conditional prerequisites only for those response types.

## Required coverage, grouped by original headings

- **Opening:** purpose and trigger→access/cooldown→response model; Commands location; Channel commands versus System commands; first-command guide as the simpler starting point.
- **Who can use this page:** default Moderator/Lead moderator/Editor/Broadcaster management; configurable action requirement; broadcaster grants VIP list access via Permissions → Actions → Commands; read-only creation reason and hidden System commands tab.
- **Make a useful reply:** New command → Name `schedule` → Sends a reply/Reply → Channel default/Starts with → Create command; enabled editor result; exact example is illustrative stream times, not a default; type `!schedule` as broadcaster/moderator, expect saved reply even offline; later changes require Save changes.
- **Choose a different response:** four choices and associated fields (Reply; numbered random replies; Pipeline; Script from Scripts); text for information, random for variety, pipeline for actions, code optional; empty-list button opens the same dialog. **Source correction:** creation also has Send the reply to for text/random replies.
- **Rules for the name:** trim ends, remove all leading `!`, lowercase; empty, internal whitespace, prefix-only, case-insensitive duplicate and >100-character names fail; error remains visible in an open dialog and nothing is created.
- **What a command does:** map dialog choices to Text/Random reply/Pipeline/Code script editor labels; pipeline/script own their delivery steps; default reply destination is Twitch chat in the channel bot voice; editor can change destination.
- **Write a reply:** helpers insert runtime information; `{stream.game}` example resolves to actual game; reply field 500-character limit; unknown-helper warning and template reference.
- **Write random replies:** select Reaction → Random reply, Edit replies, one reply per box, Add a reply, Use these replies, displayed count, then Save changes; X removes a box and is disabled for the last; pick lists are separate shared lists. **Start from another command’s replies:** copy another random command’s list; later edits are independent.
- **Triggers:** Prefix and Match are available in creation and Trigger and cooldowns editor group.
- **Prefix:** Channel default uses Bot basics’ Command prefix and falls back to `!`; Custom needs nonempty text up to 8 characters; None uses just the name.
- **Match:** case-insensitive Starts with (trigger then whitespace/end; trailing text becomes arguments), Exact (no other text), Contains (whole-word boundary, `cat` does not match `category`), Regex (pattern evaluated against message text, not an implicit full-string match); regex requires a pattern. Missing custom prefix/pattern stops creation with the named reason and disables editor saving.
- **Edit a command:** select row, edit, count unsaved fields, Save changes clears count/disables save; Discard restores saved values; refusal preserves draft and shows reason. Fields and defaults: Everyone; Text; Twitch chat/Chat overlay/Both/Nowhere (default Twitch chat); Read it aloud off; shared/personal cooldowns 0, “No cooldown”. Overlay is a loaded browser source showing bot reply. Delivery/TTS controls only for text/random; speech follows successful chat delivery, so overlay-only/Nowhere do not speak, and channel TTS must be ready; pipeline/code use their own steps.
- **Reset a command to its preset:** seeded commands alone have the button; dialog names changed fields and warns edits are lost; already matching preset reports no change. Preserve distinction from built-in reset.
- **Switch a command on or off:** row/Enabled switches save immediately; Off remains listed and answers nobody. **Source correction:** disabling a bound command can be refused until its users are moved/removed.
- **Copy a command:** Duplicate uses saved settings, opens `name-copy`, starts off, has no aliases/preset identity/reset button, defaults delivery to Twitch chat; most other settings copied; existing copy name fails visibly.
- **Delete a command:** Delete opens permanent-delete confirmation, Delete command removes row/closes editor; bound usage prevents confirmation and names category/count/up to five items. Preserve rewards, timers, chat triggers, event responses, giveaways and economy catalog-item destinations; other binding types (including scheduled tasks) can also block deletion/disable and must not be implied safe to ignore.
- **Commands that repeat a system command:** badge/banner count collisions and offer Move copies to system → Remove copies; runtime authored match wins over ordinary built-in, except `permit`, `unpermit`, `mydata`, `gdpr`, `forgetme`; removing copies is permanent. Built-in availability still depends on its saved enabled state and normal gates—do not promise removal alone always produces an answer. Banner text is not runtime precedence evidence.
- **Troubleshooting:** preserve ordered checks for Enabled, access, prefix/match, destination, both cooldowns and offline mode; platform broadcaster/moderator cooldown/offline exemptions.
- **Related pages:** retain routes to built-ins, variables/templates, cooldowns, pipelines and permissions, plus contextual links for scripts, pick lists, bot basics, first command and TTS.
