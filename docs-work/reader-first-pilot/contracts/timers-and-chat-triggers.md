## Reader, task and prerequisites

Reader: streamer/moderator who wants recurring reminders or a reply to ordinary conversation. Main question: “Should I use a timer or chat trigger, how do I make it, and when will it respond?” Success: configure a rotating reminder and a greeting trigger, save them, and correctly predict first firing, subsequent firing and matched messages.

Prerequisites: signed-in selected channel and appropriate timer/chat-trigger read/write actions (Moderator default, requirement may be raised); bot running and connected to that channel for timer checks/chat receipt. Live broadcast is not required for timers. Simple replies need no pipeline; bound reactions require an existing suitable command/action/pipeline. Overlay delivery needs its browser source loaded; simple-reply timer speech requires channel TTS readiness plus successful chat delivery. Bound reactions handle their own actions. VIP read grants allow lists only, independently per tab.

## Required coverage, grouped by original headings

- **Opening:** Triggers and timers location and two tabs; timer starts from elapsed time plus optional activity; chat trigger starts from ordinary message words; each can reply or run command/action/pipeline; distinguish a prefixed command from a chat trigger, with command guide link.
- **Who can use this page:** default Moderator and higher management roles; broadcaster can grant VIP read access to each tab; list-only/no editor and read-only explanation on New timer/New trigger; action-floor customization caveat.
- **Make a timer:** rotating two-message useful example; one message each firing, in sequence. Timers → New timer → Name → Reaction → Minutes between posts → Create timer; enabled list result, default 30 minutes. Simple reply uses Messages, one per line, blank lines dropped; Pipeline selects command/pipeline/action. Helpers such as `{channel}` work; empty-state button opens same dialog. Preserve four errors: missing name/message/target, and non-whole/out-of-range minutes (1–1440).
- **When a timer posts:** checked about every 30 s, both interval and minimum new chat lines must pass; never-fired timer is due immediately. New timer defaults activity to 0 and fires next eligible check (about 30 s, not after its first full interval). Duplicate retains activity threshold and starts off; first eligible firing uses channel’s count since watching began; after a counted firing, interval/activity measured from that firing. Activity 0 means time alone; only connected channels; timers also run offline, so disable live-only reminders manually. Messages rotate/wrap; dashboard Pipeline mode clears messages and runs bound target. Default Twitch chat, optional overlay/both/nowhere. A **simple reply** counts only when its requested delivery succeeds: Chat needs chat acceptance, Overlay needs an open receiving overlay, Both needs either, and Nowhere has nothing to deliver and counts without visible output. A failed simple-reply delivery preserves the line/last-fire state and retries at the next check. A **bound command/action/pipeline reaction** counts its recorded attempt even when invocation returns failure or the pipeline is missing, disabled, or has no executable graph; repeating timers then wait the interval and required new activity rather than retrying every check. Do not imply a counted firing proves the bound action succeeded.
- **Edit a timer:** select row, name/frequency shown; Enabled saves immediately and Off remains listed/no posts; Name, Reaction, Send the reply to (Twitch chat/Chat overlay/Both/Nowhere), whole minutes 1–1440, whole Chat lines needed 0–10000. **Post once** switches off after the first counted firing: for a simple reply after successful requested delivery (including intentional Nowhere), but for a bound command/action/pipeline after the recorded attempt even if that attempt returned failure or skipped a missing/disabled/unexecutable pipeline. It is not a promise of one successful action or visible message. Simple-reply Read it aloud follows successful chat delivery (overlay-only/Nowhere silent). Unsaved count, Save changes/Discard and refreshed list; Duplicate uses saved settings, `name copy`, off and opens editor.
- **Delete a timer:** Delete → named confirmation → Delete timer; permanently removed, no more posts, closes editor to “Pick a timer to edit it.”
- **Make a chat trigger:** Chat triggers → New trigger → Words to watch for `good morning` → Reply → Create trigger; enabled result; template helpers; default contains/case-insensitive allows `good morning everyone`; missing words/reply feedback and empty-state button. Defaults: Contains the words, Match capital letters off, 30 s, Everyone.
- **How chat must match:** Contains is substring anywhere, including longer words (`hi` in `this`); Exact requires whole line, Starts with requires beginning, Matches a pattern uses regex; case toggle; invalid regex refused at save. Do not import command Contains whole-word behavior here.
- **When a chat trigger fires:** ordinary lines only; default-prefixed lines, lines claimed by command, and soundboard-triggering lines excluded; at most one trigger per line; pattern/role/channel cooldown gates; Everyone through Broadcaster; channel wait 0–86400 s; incoming platform broadcaster/moderator bypass (stored role alone is not a bypass). A matching but cooling trigger stops further matching; below-role candidates may be skipped.
- **Edit a chat trigger:** select row with words/match summary; Enabled immediate/Off silent; words, match, case, Reaction Simple reply/Reply or Pipeline command/pipeline/action, delivery default Twitch chat, channel cooldown, role floor. Bot account voice; overlay or Both requires loaded OBS source; Save changes/Discard, saved count clears/list updates.
- **Delete a chat trigger:** Delete → named words confirmation → Delete trigger; permanent removal/no responses, editor closes to pick prompt.
- **Troubleshooting:** timer checks Enabled/Post once, activity, interval plus polling delay; trigger checks Enabled, ordinary non-prefixed input, role and channel wait.
- **Related pages:** preserve links to Create a command, Pipelines, Variables and templates, Permissions and delivery guidance.

## Evidence limits

Polling timing is approximate and assumes a running, connected worker; no live timer/chat/OBS/TTS test was run. Do not promise exact-to-second posts, that target invocation failures retry every poll, or that Post once guarantees a successful bound action. The counted-attempt behavior above concerns ordinary returned outcomes: an exception before a reaction returns bypasses the later state-write block and is caught by the per-timer outer handler. Source corrections are identical requirements for both variants. The four reader questions remain unchanged because their timer case explicitly uses Simple reply; this correction is an additional mandatory fact check on both full articles.
