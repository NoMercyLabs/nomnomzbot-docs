title: Timers and chat triggers
description: Make a rotating reminder or a reply to ordinary chat, then choose when it responds.
---

For a reminder you want to repeat during a stream, use a timer. It waits for time to pass and, if you choose, for enough new chat messages. To answer something viewers say in conversation, use a chat trigger: someone writes `good morning`, and the bot welcomes them.

Open **Triggers and timers** in the sidebar. **Timers** holds the scheduled reminders; **Chat triggers** holds the replies to ordinary messages. Either can send a simple reply or run a command, action or pipeline, which combines several actions.

A chat trigger does not need the leading `!` that starts a command such as `!hello`. That leading text is the command's *prefix*. To make a command viewers ask for by name, use [Create a command](/reference/commands/create-a-command).

## Who can use this page

Sign in and select your channel. By default, a **Moderator**, **Lead moderator**, **Editor** or **Broadcaster** can change its timers and chat triggers. The broadcaster can raise the required role on **Permissions**.

The bot must be running and connected to the channel to check timers and receive chat. Timers can post while the stream is offline, so switch off a reminder when you finish if you only want it during broadcasts. A simple reply needs no existing command or pipeline.

The broadcaster can also grant a **VIP** read access to either tab independently. A VIP sees that tab's list, without an editor. **New timer** and **New trigger** show “You can view this, but your role cannot change it.” The roles and access settings are explained on [Permissions](/reference/settings/permissions).

## Make a timer

Make a break reminder with two messages. The bot will post one each time, in order, so it can vary the reminder without sending both at once.

A new timer starts switched on with **Chat lines needed** at 0. Its first message is due at the next timer check, usually within about 30 seconds; it does not wait a full 30 minutes first.

1. Open **Triggers and timers**, then **Timers**, and choose **New timer**.
2. Type `Break reminder` in **Name**.
3. Leave **Reaction** at **Simple reply**. In **Messages**, enter these two lines:

   ```text
   Take a moment to stretch and get some water.
   New here? You are welcome to join the conversation or just watch.
   ```

4. Keep **Minutes between posts** at its default, **30**, and **Send the reply to** at **Twitch chat**. Leave the other options alone for now.
5. Choose **Create timer**. The dialog closes and the timer appears in the list, switched on.

Watch your channel's chat for “Take a moment to stretch and get some water.” After the next 30-minute wait and an eligible timer check, the bot posts the second line.

When the tab has no timers, **Make the first timer** opens the same dialog as **New timer**. Blank lines in **Messages** are dropped.

For a different reaction, choose what the timer should do:

| **Reaction** | What to enter |
| --- | --- |
| **Simple reply** | **Messages**, one message per line. |
| **Pipeline** | An existing command, [pipeline](/reference/commands/pipelines) or action in **Pipeline**. |

A message can include a helper such as `{channel}`, which the bot replaces with the channel's value. See [Variables and templates](/reference/commands/variables-and-templates) when you want changing information in a reminder.

The dialog stays open and shows a reason in red if it cannot create the timer:

| Problem | Message |
| --- | --- |
| No name | “Give the timer a name.” |
| **Simple reply** with no message | “Write at least one message.” |
| **Pipeline** with nothing selected | “Pick the command, action or pipeline the timer runs.” |
| Minutes are not a whole number from 1 to 1440 | “Use a whole number from 1 to 1440 minutes.” |

## When a timer posts

The bot checks timers about every 30 seconds, and only for channels it is connected to. After a timer fires, both its waits must pass before it fires again:

- **Minutes between posts** measures time since the last firing.
- **Chat lines needed** counts new chat lines since that firing.

With **Chat lines needed** at 0, time alone is enough. A timer that has never fired is already due, subject to its chat-line requirement. That is why a new timer can post at the next check.

**Duplicate** keeps the original timer's chat-line requirement and starts switched off. Once enabled, the copy can first fire when the channel has had that many messages since the bot began watching it. After that first firing, its activity wait is measured from the previous firing, like any other timer.

Several messages rotate in order, one per firing, then wrap back to the first. Changing a simple-reply timer to **Pipeline** in the dashboard clears its messages; each firing runs the selected command, pipeline or action instead.

For simple replies, **Send the reply to** starts at **Twitch chat**. You can choose **Chat overlay**, **Both** or **Nowhere**. Overlay delivery needs its browser source loaded in OBS. The shared delivery and appearance controls are explained on [Create a command](/reference/commands/create-a-command).

For a simple reply, the timer counts a firing according to the delivery you chose:

| Delivery | What counts |
| --- | --- |
| **Twitch chat** | Chat accepts the message. |
| **Chat overlay** | An open overlay receives the line. |
| **Both** | At least one of chat or the overlay receives it. |
| **Nowhere** | The firing counts without visible output. |

If delivery does not meet that rule, the timer keeps the same line and timing state for the next check. A bound command or action counts its attempt even when it reports failure. A pipeline attempt also counts when it reports failure or the pipeline is missing, disabled or has no executable graph. Repeating timers then wait for their interval and new chat-line requirement; the recorded firing does not prove the action succeeded. An unexpected error before the reaction returns leaves that firing unrecorded.

The stream being offline does not stop a timer in a connected channel. Switch it off to stop a live-only reminder.

## Edit a timer

Choose a timer in the list to open its editor. The list shows its name and how often it posts.

| Field | What it changes |
| --- | --- |
| **Enabled** | Saves immediately. An off timer stays listed as **Off** and posts nothing. |
| **Name** | The name in the list. |
| **Reaction** | The message replies or the command, pipeline or action to run. |
| **Send the reply to** | **Twitch chat**, **Chat overlay**, **Both** or **Nowhere** for a simple reply. |
| **Minutes between posts** | A whole number from 1 to 1440. |
| **Chat lines needed** | A whole number from 0 to 10000. |
| **Post once** | Switches off after one counted firing, using the rules in [When a timer posts](#when-a-timer-posts). |
| **Read it aloud** | For a simple reply, requires the channel's text-to-speech setup to be ready and speaks after successful chat delivery; an overlay-only reply or **Nowhere** stays silent. Bound reactions follow their target's behavior. |

For a simple reply, **Post once** waits for successful delivery under those rules; **Nowhere** intentionally counts without a message. For a bound reaction, a recorded failed attempt can switch the timer off too, including a skipped missing or disabled pipeline. It does not guarantee one successful action.

The footer counts unsaved changes. Choose **Save changes** to keep them, or **Discard** to return to the saved timer. After saving, the count clears and the list shows the new values.

**Duplicate** copies the saved settings, including the chat-line requirement, rather than your unsaved edits. It adds “copy” to the name, such as `Break reminder copy`, and opens the copy in the editor, switched off.

## Delete a timer

1. Open the timer and choose **Delete**. The confirmation asks “Delete *name*?”
2. Choose **Delete timer**.

The timer is permanently removed and stops posting. Its editor closes to “Pick a timer to edit it.”

## Make a chat trigger

Let the bot answer a morning greeting without asking viewers to remember a command.

1. Open **Triggers and timers**, then **Chat triggers**, and choose **New trigger**.
2. In **Words to watch for**, type `good morning`.
3. In **Reply**, type `Good morning! Settle in and enjoy the stream.` Keep **Send the reply to** at **Twitch chat** and leave the other options alone.
4. Choose **Create trigger**. The dialog closes and the trigger appears in the list, switched on.

Write `good morning everyone` as an ordinary message in your channel's chat. The bot replies “Good morning! Settle in and enjoy the stream.” The default match accepts those words anywhere in the message, without caring about capital letters.

The reply can also use helpers from [Variables and templates](/reference/commands/variables-and-templates). When the tab is empty, **Make the first trigger** opens the same dialog. Missing fields show “Give the trigger some words to watch for.” or “Write the reply.”

A new trigger uses these settings, which you can change in its editor:

| Setting | Default |
| --- | --- |
| **How chat must match** | **Contains the words** |
| **Match capital letters** | Off |
| **Seconds between replies** | 30 |
| **Who can set it off** | **Everyone** |

## How chat must match

Choose how closely a chat line must follow **Words to watch for**:

| Choice | When it matches |
| --- | --- |
| **Contains the words** | The text appears anywhere, including inside a longer word. |
| **Is exactly the words** | The whole chat line is that text. |
| **Starts with the words** | The chat line begins with that text. |
| **Matches a pattern** | The chat line matches a regular expression, a pattern language for text. |

For example, `hi` with **Contains the words** also matches `this`. Choose **Is exactly the words** to answer only the greeting, or use a suitable pattern for a more specific rule.

With **Match capital letters** off, `Hello` and `hello` match the same way. Turning it on makes them different. An invalid regular expression is refused when you save.

## When a chat trigger fires

Chat triggers watch ordinary chat lines. A line starting with the channel's command prefix is excluded, even when it does not run a valid command. A line claimed by another command or by a soundboard trigger is excluded too.

One line can fire at most one chat trigger. The bot checks the text, then **Who can set it off**, then **Seconds between replies**. It can skip a matching trigger if the sender does not meet its role requirement. If an eligible match is cooling down, the search stops; another trigger does not answer instead.

**Who can set it off** is the lowest role allowed, from **Everyone** through **Broadcaster**. **Seconds between replies** is a wait for the whole channel, from 0 to 86400 seconds (one day), starting when an eligible match fires.

The broadcaster and moderators identified on the incoming platform message bypass that wait. A role stored only in the bot does not grant the bypass.

## Edit a chat trigger

Choose a trigger in the list to open its editor. The list shows its words and match choice.

| Field | What it changes |
| --- | --- |
| **Enabled** | Saves immediately. An off trigger stays listed as **Off** and answers nothing. |
| **Words to watch for** | The text the bot looks for. |
| **How chat must match** | The rule in [How chat must match](#how-chat-must-match). |
| **Match capital letters** | Whether `Hello` and `hello` are different. |
| **Reaction** | **Simple reply** sends the **Reply**. **Pipeline** runs an existing command, pipeline or action instead. |
| **Send the reply to** | Where a simple reply appears; **Twitch chat** is the default. |
| **Seconds between replies** | The channel's wait before the trigger fires again. |
| **Who can set it off** | The lowest role allowed to fire it. |

The default reply comes from the channel's bot account in Twitch chat. To show it on stream, keep the chat overlay's browser source loaded in OBS and choose **Chat overlay** or **Both**.

Choose **Save changes** to keep edits, or **Discard** to return to the saved trigger. Saving clears the unsaved count and updates the words in the list.

## Delete a chat trigger

1. Open the trigger and choose **Delete**. The confirmation asks “Delete *words*?”
2. Choose **Delete trigger**.

The trigger is permanently removed and stops answering. Its editor closes to “Pick a trigger to edit it.”

## Troubleshooting

::Troubleshooting

**A timer never posts.**

1. Check **Enabled**. A timer marked **Off** posts nothing; **Post once** switches it off after one counted firing, which can be a failed bound-reaction attempt.
2. Check **Chat lines needed**. A quiet chat holds the timer until enough new lines arrive.
3. Check **Minutes between posts**. After the interval passes, the next check can add about 30 seconds to the wait.

**A chat trigger does not answer.**

1. Check **Enabled**. An off trigger answers nothing.
2. Send an ordinary chat line. A line starting with the command prefix cannot fire it.
3. Check **Who can set it off** against the sender's role.
4. Check **Seconds between replies**. The channel may still be waiting after the previous firing.

::
