# Skill findings (Atlas), 2026-10-28

Recorded during the user guide run. The skill was not edited.

1. Reader reviewer (agents/reader.md) has no blocking threshold. Every round the model raises new small points, and a page takes five to seven rounds to reach PASS (pilot page 7 rounds, overview 6, sign-in 5). Proposed rule: the reader splits findings into "Blocking" (leaves the reader unable to act, or a term used before it is taught) and "Notes" (wording preferences). Only Blocking findings set FAIL. Notes never set FAIL.
2. The fact-checker and reader run on pages whose repair is new text, so each repair round costs two reviews. Proposed rule: the fix round lists the exact changed passages and the reviewer must re-judge the whole page but may cite earlier cleared findings as settled (the reader template already says this; the manager must carry the list of cleared findings in the dispatch).
3. Scanner slices of 7,500 lines of source exceed a 150k context budget. Proposed rule: cut slices at 4,500 lines.
4. The checker's `map` gate accepts a coverage root set chosen by the run. The skill does not say how to pick roots for a product with a large server tree. Proposed rule: state the root choice in scope.md and list the unread layers as excluded.
5. Three managers editing the same `map.md` Status column cause Edit conflicts. Proposed rule: one status file per queue, merged by the main session, or the checker reads status from the verdict files.
6. (2026-10-28, template reader batch rd1) The Atlas reader role names the verdict file `docs-work/reviews/<slug>.reader.md`. The template helper batch uses `docs-work/reviews/reference-templates-<slug>.reader.md` and `reference-commands-variables-and-templates.reader.md`, because slugs repeat across sections. Proposed rule: the reader role takes the verdict path from the dispatch, with the page's section as a prefix.
7. (2026-10-28, template reader batch rd1) The reader role's density rule (over three sentences per paragraph, with paragraphs read as blank-line blocks) is not enough to make a reader fail a page. Each reader must also check that every helper named in an intro has a table row. Proposed rule: the reader template adds the check "every name in the intro is found in the body", and a missing name is blocking.
